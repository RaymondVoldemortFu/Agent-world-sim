# 空间依赖并行调度

模型请求按安全批次并行，物理动作和事件仍按原来的 ID 升序提交。浏览器默认最多 6 个请求，Python 代理默认允许 8 个上游请求；日末结算保持单次串行执行。

## 独立性的判定

角色的观察半径为九宫格，即切比雪夫距离 1；一个动作最多移动 1 格。因此两人当前距离为 2 时，先行动的人可能走进另一个人的视野，后者必须等待最新观察。**同批角色两两距离必须大于 2**。

还需处理非空间依赖：双方存在未完成、未撤回且尚未过期的共同动作提议时，即使已经走远，也保持串行。撤回提议会改变另一方看到的提议状态。

制造、采集、攻击、给予、喂食和改造的物理作用都局限于当前地块；chat 的传播半径为 1，shout 的传播半径为 2。两格内的听众不会并行预取，三格外可继续并行；shout 不移动角色，因此现有距离边界已覆盖它。上述距离边界覆盖当前动作集合。未来加入远程攻击、传送或全局广播时，必须更新作用范围和对应测试。

## 为什么采用连续 ID 批次

从当前待执行 ID 开始向后选择角色，遇到与已选角色存在依赖的角色就结束本批，不跳过它继续选更大的 ID。

例如 A 与 B 相邻，C 与 A 很远但与 B 相邻。如果跳过 B 提前请求 C，B 尚未发生的行动仍可能改变 C 的观察。连续前缀避免此类跨批次的隐含依赖。

批次执行流程：

1. 生成并复制每位角色的独立观察，持久化各自的 pending 决策。
2. 同时发起模型请求，等待本批所有请求完成或失败。
3. 按 ID 顺序重新校验并原子提交，每个动作有独立决策 ID 和事件序号。
4. 根据最新位置及提议状态选择下一批。

每 5 天的反思只修改本人私有认知，因此可在同一反思阶段并行请求，仍按 ID 提交。所有批次都不跨日、不跨微回合。

## 暂停、恢复与预算

暂停会等待已发起的请求返回并保存，按顺序提交可执行部分，随后停止派发。若某个决策发生配置错误，后续已返回但未提交的结果保留在各自的 pending 记录中。

命令行使用 `pending/<决策ID的SHA-256>.json`，浏览器使用 IndexedDB 的独立决策行。恢复前会比较缓存请求上下文与当前观察；不一致时保存旧尝试记录并重新请求，避免应用陈旧结果。

预算在批次开始前检查，首次请求数量不超过剩余调用次数；格式修复和网络重试仍可能让最后一批超过阈值，最大增量受批次大小和每个决策的重试上限约束。墙钟耗时单独记录，不再以并发请求耗时之和替代。

调整方式：

```bash
npm run simulate -- --mode llm --out artifacts/llm-baseline --resume --concurrency 6
```

界面下方的「并发 6」菜单可设为串行、2、4、6、8；运行中修改从下一批生效。后端环境变量 `MAX_CONCURRENT_REQUESTS` 限制所有本地实验合计的上游并发，修改后需要重启后端。

## 已验证的结果

- 单元测试：移动边界、连续前缀、远距离共同提议、缓存上下文隔离，以及固定动作序列下并行/串行的逐次观察与最终状态一致。
- 浏览器测试：多个远处角色同时请求，暂停后事件仍按 ID 递增提交。
- 真实模型试跑：20 人 × 1 天，6 并发上限，61 次模型调用，约 28.4 秒。此前同 seed、同初始规模的串行第一天约 77 秒，实际耗时约缩短至 37%。LLM 采样和请求耗时存在波动，这不是固定倍数保证。

正式 100 天实验也已完成。并行阶段按规则重建为 1,007 批、4,961 次角色决策，平均每批 4.93 人；该阶段所有保存的观察与串行顺序下的行动前状态一致。完整数据及早期日志来源说明见 [MVP 运行报告](MVP_RUN_REPORT.md)。

## 吞吐量的边界

并发上限为 6 不意味着耗时固定缩短为六分之一。相邻角色会切分批次，每批还需等待最慢的请求及其重试；提交、持久化和日末结算也需要时间。反思输出通常更长，因此每 5 天的反思阶段会稍慢。

后续若仍需加速，可将连续批次扩展为微回合内的有向依赖图：角色仅在所有较小 ID 的依赖前驱完成后请求，独立分支可持续填满空闲请求槽。需要覆盖移动造成的观察变化、共同提议和故障恢复，并再次验证每份预取上下文与按顺序执行时一致。当前实现先以连续批次建立这套一致性基线。


## 免费丢弃与连续行动

`mvp-1.2.0` 中每人每日 4 AP，成功丢弃不消耗 AP。丢弃后保持当前 ID 的普通行动机会，通过 `freeActions` 序号分配新的独立决策 ID；后续的付费动作完成后才轮到下一位角色。非法丢弃仍消耗 1 AP，避免空库存重复丢弃导致无限循环。

如果同批较小 ID 免费丢弃，较大 ID 已返回的响应保留在 pending 中，下次批次通过上下文校验后复用。成功丢弃只影响本地地面和库存，不会扩大空间依赖范围。暂停/恢复沿用这一规则，既不重复调用已收到有效响应的模型请求，也不提前提交较大 ID。

`mvp-1.5.0` 默认每日 5 AP。`drop` 免费销毁背包物品，仍保留当前普通行动机会；`place` 消耗 1 AP 将物品放到地上，其影响保持局部，按普通付费动作推进调度。

`mvp-1.6.0` 的全力观察在动作提交时采样三格环境，结果保存为私有且冻结的快照。随后决策只读取固定快照和当前九宫格，不实时读取三格远处状态，因此空间冲突半径保持 2。回归测试覆盖同批先提交远处死亡、随后全力观察捕获尸体，且预取输入未被污染。
