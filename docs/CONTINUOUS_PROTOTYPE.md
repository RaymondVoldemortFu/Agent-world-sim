# 连续世界第一版

当前三维游戏引擎及新实验规则见 [GAME_ENGINE_UPGRADE.md](GAME_ENGINE_UPGRADE.md)。以下记录对应 `continuous-prototype-1` 版本。

2026-09-11。入口：`http://127.0.0.1:5173/?engine=continuous`，旧页面导航也有“连续世界”链接。总体方案见 `CONTINUOUS_WORLD_V2.md`。

## 已实现的体验

- 榆树村五人原型：18×16 地块，每格15米；两户住宅、大厅内的粮箱、庄园围墙与可开关的门、八块田、广场、井与工棚。
- PixiJS 独立渲染循环：等距地面、材质细节、木石建筑、作物、树木、人物肢体动画、屋顶淡出；支持拖动、缩放、点击人物与地点、路线显示。
- 时间固定720倍：现实120秒经过游戏一天。暂停停止推进，继续不补算暂停时间。默认150天约需5小时。
- 连续路径运动与中途换目标；门和钥匙决定路线能否通过。行走耗时由路径长度、负重与健康确定。
- 持久任务：前往地点、补粮到目标数量、存粮、农活、休息/驻留。进食只扣随身粮食，取粮先预留有限库存；任务取消释放预留；劳动中断保留真实进度。
- 自动日程可由 Agent 配置。LLM 开局仅自动进食；补粮和农活默认关闭。脚本演示单独启用预定义的补粮/工作安排。
- 讲话可伴随行走/轻劳动；公开交谈12米、喊话75米；在实际发言完成时确定活着的听众。第一版以整句为传递单位。
- 饥饿按游戏时间积分：2500 kcal/人日，空腹15 HP/日，按半小时边界检查死亡与应急进食。死亡保留尸体及随身库存。
- 右侧显示实际动作、计划、阻塞原因、连续位置、随身口粮、routine、思考状态及事件历史。观察者可以切换导航目标、中断任务、控制庄园门。
- MySQL 精简事件、路径段、可恢复任务和定期快照；时间轴可查询任意历史时刻，支持10倍游戏时间的回放慢放。回放操作不更改当前世界。

## 两种运行模式

**脚本演示**用于验证行为执行与视觉，完全不调用模型。

**LLM自主**使用当前 `.env` 中配置的模型供应商。每人至多一个在途请求，每实验默认最多5个，可在配置中改为1–8个，全局最多8个；首次并发规划，随后通常每半个游戏日一次，失败有间隔。规划按实验进度持续调度，调用次数与累计token仅用于统计；历史存档中的maxCalls/maxTokens字段不再参与调度。上下文窗口用于触发历史压缩，模型请求不设输出截断参数；压缩调用计入真实token用量。

共享世界规则、共知地图、人格背景位于固定前缀。复用现有人格提示生成器；每人的观察变化、现场经历与准确的模型回复追加到 MySQL 上下文。达到所配置上下文窗口的85%估算token时调用模型压缩活动历史（默认窗口100k），保留固定前缀，原始请求结果与事件可外部查询。模型请求不设置输出截断参数，动作字段仍需满足schema。

原型协议与旧版 `context-1` 独立：当前未迁移旧实验的全部配方、知识查询、十日深度反思和外部记忆检索动作。每次新增观察只含本人身体/任务、30米内的可见居民与库存，以及实际收到的事件；不会把全局库存放进角色上下文。模型回复只有通过校验并在当前计划版本仍适用时才接纳；等待期间新发生的事件保留。

## 执行与持久化

| 组件       | 路径                                              | 职责                                                |
| ---------- | ------------------------------------------------- | --------------------------------------------------- |
| 纯TS内核   | `frontend/src/continuous/{types,world,engine}.ts` | 世界、解析轨迹、事件推进、物资和任务                |
| Node服务   | `scripts/continuous/server.ts`                    | 8001端口，单writer队列、墙钟推进、异步模型邮箱、SSE |
| Python服务 | `backend/app/continuous_api.py`                   | 8002端口，MySQL事务、回放和模型上下文               |
| 地图页面   | `frontend/src/continuous/{Page,Scene}.tsx`        | 只读呈现、控制与历史回放                            |

Node约每100ms推进到对应模拟时间并提交，网络开销通过下一次墙钟差值追赶。磁盘只保存语义事件与动作中已有的路径，不保存每个渲染帧。最新恢复状态覆盖更新，每6游戏小时增加一份历史快照；写入核对事件序列、单调时间和回放结果与提交状态的一致性。只有已经提交的数据能广播。

前端保存短期已提交历史缓冲，并展开同一网络批次里的多个动作状态，用350ms延迟播放已提交轨迹。断线重连以完整已提交快照恢复。模型调用在world提交队列外进行；旧版本回复和重复回调不会重复执行交付。

服务重启后，打开实验会从MySQL恢复并保持暂停；已有完整模型结果尽量从请求ID对应的记录恢复，无法确定的调用记录为失败而不直接重发。未提交时间不作为已发生事件发布。单实例由8001监听端口约束；分布式多writer租约与跨主机恢复尚未实现。

素材均由本地Pixi Graphics程序绘制，未使用外部版权图片，也未引入额外素材下载依赖。新页面采用懒加载，旧实验页面不加载地图引擎。

建筑美术集中在 `frontend/src/continuous/art.ts`：等距三维坐标生成分层建筑、逐片屋瓦、木构与斜撑、石材接缝、铅框窗、百叶窗、花箱、橡木门、门阶、工棚雨棚、旗帜、木桶和粮袋。城墙由相接墙段组成；人物有头巾/帽子、围裙/外衣、腰带和携行小袋。支持围绕鼠标缩放观察细节；室内未选中居民被建筑遮挡，选中时剖开屋顶。截图见 `artifacts/continuous-art-overview.png` 与 `artifacts/continuous-art-detail.png`。

## 启动

完整开发环境：

```sh
npm run dev
```

旧API/Vite已在运行时，仅启动新服务：

```sh
npm run dev:continuous
```

Vite将 `/continuous-api` 转发到8001。Python服务使用现有MySQL配置和模型配置，首次启动自动创建独立 `continuous_*` 表，不修改旧实验数据。旧实验与连续实验共用导航、启动窗口和实验档案，数据模型与存档分别保留。

## 实施范围与下一阶段

本版是设计中的A阶段，并提前接上最小异步LLM计划链。可用于检验执行协议、时间节奏和观看体验，尚不是完整中世纪政治实验的替代版本。

下一阶段需迁移：31人领地背景、税收/使者/王军、武器和战斗、个人账簿/铭文、完整领地统计和新闻页、十日深度反思、完整外部记忆查询；再细化建筑碰撞多边形、人物间避让和门口排队。当前墙与门阻挡移动，居民之间可以通过同一路段，住宅/大厅以交互锚点而不是独立室内导航图表示。当前道路主要为视觉地标，导航最短路径可穿越草地。

农业使用原型数值：每田每月满额30人日粮、需120人小时劳动，D40后减产一半。该小场景数值用于工作流程测试，不能代替完整领地的税粮平衡分析。疲劳、睡眠、体力与攻击通道将在后续移植时标定。

验证命令：

```sh
npx vitest run frontend/tests/continuous.test.ts
MYSQL_TEST=1 uv run --project backend python -m unittest backend.tests.test_continuous -q
npx playwright test frontend/tests/e2e/continuous.spec.ts
npm run build
```

针对性验证涵盖时间比例、连续中途位置、门与钥匙、库存竞争、取消释放、跨日劳动、讲话听众、迟到/重复模型回复、思考期间执行、暂停、饥饿积分、恢复和事件一致性。浏览器验证创建、选人、决策历史、关门、干预与只读回放。真实模型小规模验证另保存到MySQL；日长实测见 `artifacts/continuous-timing.json`。

原型初次验证结果：12个TS内核用例、3个MySQL/模型传输用例、1个浏览器集成用例通过，生产构建通过。真实模型并发5次，全部返回合法计划，合计7218 tokens；已观察到5次取粮、10段行走和后续农活，验证后暂停。日长实测120.010现实秒推进0.999402游戏日，折合约82ms现实时间的观测偏差，处于一次100ms推进周期内。重启后读取两个真实原型档案，当前状态均与相同时刻的MySQL回放一致。


## 统一界面与对话分析

在原有“开始新实验”窗口选择“连续村庄 · 2.5D”，选择脚本或LLM控制器，填写天数、规划请求上限、并发、上下文窗口和背包容量。参数通过Node服务校验并写入初始世界；调度器和模型网关使用存档中的配置。“配置”页展示本轮实际值，“配置下一次实验”打开新实验草稿。时间比例仍固定为120现实秒/游戏日。老连续存档缺少settings时，使用原有天数、请求数和人物容量，并为新字段补默认值。

规范链接为 `/?engine=continuous&run=<ID>&page=<页面>`；原 `?page=continuous&run=<ID>` 链接会自动进入统一界面。世界、配置、统计数据和对话分析已接入，实验档案可打开两种模式。连续页以SSE接收状态，切换页面保留连接、选人和回放；离开地图时暂停Pixi渲染。连续模式不会启动旧浏览器模拟Worker，也不会展示旧实验的数据。Agent经历目前在地图右侧查看，铭文、新闻及完整经历查询仍待相应内核数据迁移。

对话分析使用 `dialogue-village-2`：新增核账/交付确认、协商/交易条件、指令/催办催缴、风险告警意图；新增家庭储备、税收欠税、权力与反抗、守卫门禁、家庭邻里、账簿公告、自动任务主题。保留历史产业类别以便读取原有实验。库存中的谷物不再仅因出现“谷/粮”就标成田间劳动。明确的否定会抑制肯定同意等局部线索；特定事务短语优先于泛化状态通报。类别为规则匹配，不提供真实性判断或政治事件判定。图表显示多标签频数、合作/核账/告警/冲突时间线以及实际听众关系，保留原文证据与字符TF-IDF相似检索。

`GET /continuous-api/runs/<ID>/dialogue?after=0&through=<seq>&limit=1000` 提供按序前进的稀疏分页。MySQL索引 `(run_id,kind,seq)` 只读取speaking和speech，响应剔除状态patch。开始发言只帮助恢复老档案的频道，完成发言才计数；新事件显式记录channel。浏览器Worker跨页保留频道状态，使用实际listeners构建关系图。through冻结本次分析边界，刷新分析才纳入新发言。分析和回放端点不激活模拟实例，不产生模型请求。“回放发言现场”定位对应游戏时刻。

新增验证覆盖：参数持久化与旧档案兼容、稀疏分页边界和旧频道恢复、新分类/否定样本、配置控制压缩阈值，以及统一启动→配置→统计→对话→回放→档案的浏览器流程。脚本测试不会调用真实模型。

统一界面验证结果：19个前端内核/分类/配置用例、4个MySQL/模型传输用例、4个浏览器用例通过，生产构建通过。浏览器用例覆盖新旧两种数据源和390px窄屏布局。
