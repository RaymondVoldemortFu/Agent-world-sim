# 世界统计与 Agent 经历页面

导航提供“统计数据”和“Agent 经历”。URL 的 `page`、`agent` 参数保留页面及居民选择；可以从统计页居民表直接进入该居民的经历。

## 统计数据

从当前检查点汇总，跟随原有快照刷新；历史回放时显示对应时点。人口、生命、饱食、孤单、抑郁和妊娠均按活人统计，无活人时均值显示“—”。日趋势来自已经完成的日结，交流和请求曲线由累计计数差分得到。

生态食物以 FD 表示（2,500 kcal），包括活人背包、地面和仓储的剩余食物热量，不包括体内能量、待收作物和在制投入。风险 ≥0.5 的食物单列，但仍包含在总数内。野生食物现存量不等于每日或年度产出。旧世界仍按份数显示。

区域表显示人口、地面与仓储食物、田块面积、建筑完成情况。工序区统计进行中、完成、取消和多人参与任务。资源表以 kg 分开列出自然生物量及矿藏、活人背包、地面、仓储与工序投入；矿藏 kg 是矿石质量。

调用面板显示输入、输出和缓存 Token、错误、修复、规则/持续计划/模型/降级执行及估算费用。缓存 Token 属于输入 Token，不重复相加。没有价格配置时不显示虚构金额。

## 经历查询

按 Agent、关键词、亲历/听闻/个人判断、起止日查询，每页 60 条。查询固定已提交事件边界；“刷新经历”读取新的历史。死亡居民仍可查询。界面明确区分历史上记录过的经历和角色当前保留的最多 200 条记忆。

后台从事件补丁的 `agents[].memories` 与 `agentChanges[].memories.append` 增量提取记忆，按 Agent ID 和记忆 ID 去重。历史缓存淘汰不会删除查询索引。经历携带来源、讲述者、重要性、事件引用和关联行动决策。后者属于行动发起者，不能当成听众的私有决策。

SQLite 经历索引与世界纪事共用缓存文件，但独立记录扫描位置；已有纪事索引无须为新功能重建。追加只读取新增完整行，日志截断或替换后重建。当前大实验首次索引约 41 秒，后续样本查询 3–29 ms；这是本机函数计时，不含防抖、网络与渲染。索引不会改变 Agent 自己能回忆的内容。

本地 IndexedDB 导入使用页面内增量缓存，同样从历史事件读取和去重。只有保存在事件日志中的记忆能被检索；缺失的历史不会从当前状态推测补全。

## 验证

- 后端覆盖 Agent 隔离、早期被淘汰记忆、重复完整状态补丁、来源/关键词/日期筛选、已提交边界、分页、追加和截断恢复。
- 数值检查覆盖库存分列、食物能量口径、死亡角色排除与全灭均值。
- 浏览器覆盖生态统计、手机宽度、居民跳转、本地/后台经历查询、关联决策、日期校验、分页和刷新后保留居民选择。
