# 当日新闻流

“当日新闻”页为人类观察者提供独立 LLM 报道。打开 MySQL 实验后，点击“开启新闻流”，后台从 D1 顺序补齐已结束日期，随后自动处理新的日末；关闭页面不影响生成。可暂停、继续和重试；暂停允许当前一期完成。浏览页面和翻页只读已保存结果，不调用模型。

## 数据边界

以按序排列的 `day_end` 事件作为当天不可变结算边界，回放到该事件获取仓储库存及所有个体的存活、离场、HP、饱食度和已记录死因。相邻日末序号之间成功完成的 chat、public_speak、shout 全部按序输入，保留人物、听众、原文和 E 编号；不计启动日志与失败对话。使用事件边界而非 `day_end.day` 字段，因为旧结算实现会在事件提交前推进日期。仓储原料合并为按物料 kg 的表格；空仓仍保留。私人记忆、决策与账簿内容不进入新闻材料。

新闻必须区分物理事实、对话主张与推断。昨日报道仅作背景，不能成为今天承诺已兑现的证据。新闻不进入 Agent 上下文，也不参与世界回放状态。UI 在历史回放时按日末序号屏蔽未来报道。

## 缓存与窗口

固定编辑规则在 system prefix，初始人物索引和单位定义是实验级不变前缀。每期只保存新增 user 材料与原样 assistant 报道，下一次重建完全相同的已有消息前缀，再追加当天数据。昨日新闻自然位于上一条 assistant 消息；不改写旧快照、不重复拼接昨日新闻。

窗口 100k；请求不发送 max_tokens 等输出截断参数，2k tokens 仅用于发起请求前估算上下文余量，实际用量按供应商响应计费。估算输入接近 75k 时开始新的上下文段，保留固定前缀、昨日新闻和今日完整材料。界面显示当前段起始日。75k 阈值为实际分词差异预留余量，缓存命中以供应商返回数据为准。

若单日超窗，所有对话按完整事件分组取证（每组估算最多24k），复用固定前缀、昨日新闻及今日状态；再综合全部证据提要。过多提要继续分组归并。不会静默丢弃尾部对话；单条事件或个体/仓储状态无法容纳时明确失败。分段报道在 UI 标记。超大日会产生额外模型调用。

## 后台与存储

- `news_streams` 保存自动续写开关与固定前缀；`daily_news` 保存压缩的每日增量上下文、报道、证据边界、摘要链哈希与计数；`news_attempts` 保存实际供应商用量、失败和延时，独立于 Agent 预算。
- 后台新闻任务顺序处理每个实验的下一天，与模拟进程分离，共用供应商并发限额。MySQL 实验级 advisory lock 防止多个服务进程重复生成；锁不锁定实验状态或资源。已存在日期直接返回缓存。
- 失败时保留已有新闻并暂停此实验的自动续写；重试从缺失的下一天继续。只有完整返回的报道入库。服务重启后恢复已开启的队列。
- `GET /api/experiments/{name}/news?before=...&through=...` 分页查询，`POST` 的 `{enabled:true|false}` 控制续写。新闻数据为独立的派生视图；原实验导出格式尚不包含这三张表，可从日志重新生成。

验证包含日末边界、对话完整性与去重、私有数据隔离、消息前缀完全相等、超窗轮换/完整分段、重复请求不重复生成、失败不跳日、历史屏蔽，以及页面翻页、暂停继续和安全文本渲染。
