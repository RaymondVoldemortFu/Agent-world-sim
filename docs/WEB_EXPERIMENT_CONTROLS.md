# Web UI 实验控制

顶部「开始新实验」打开初始配置，可选择 LLM 或脚本模式、并发数以及完整世界参数；「启动后台实验」在独立的 `artifacts/web-日期时间-随机标识/` 中初始化并运行。已有实验保留，浏览器地址自动切换到新实验，刷新页面后仍打开同一轮。

后台实验地图下方提供「中断实验 / 继续实验」。中断请求标记当前运行进程，执行器在当前批次完成提交后导出并退出，页面先显示「正在保存」，进程退出后才允许继续。继续沿用 checkpoint、请求缓存、模式与并发数；同一实验只允许一个进程写入。已完成实验和不兼容的旧规则实验不允许继续。浏览器运行方式仍使用原有 Worker 控制。

接口：

- `POST /api/experiments`：传入 `config`、`mode`、`concurrency`，创建并运行。
- `POST /api/experiments/{name}/pause`：请求中断，重复请求安全。
- `POST /api/experiments/{name}/resume`：从保存点恢复，运行中或保存中返回 409。
- `GET /api/experiments/{name}/control`：读取状态、原因及是否可继续。
- 现有 snapshot 接口同步携带 `control`，页面沿用原有快照刷新。

TypeScript 执行器继续独占世界状态。后端通过参数数组启动 Node，通过带进程 ID 的控制文件请求中断。运行锁、日志、模式和状态持久化在实验目录，因此后台服务重新启动后仍可识别运行进程。`runner.log` 保存后台输出；新配置由共享的 `ConfigSchema` 校验。

验证：3 项真实子进程/API 测试覆盖保存恢复、日志连续性、重复启动保护、独立创建、完成状态及无效输入；7 项现有代理测试通过；2 项浏览器测试覆盖控制状态、失败反馈和从表单实际启动脚本实验；TypeScript 与生产构建通过。未运行全量测试。
