# 鸦溪领地：月度农业、家庭与王税

实现版本：`manor-1.0.0`。在新实验中选择“中世纪鸦溪领地”；新实验表单默认选择此场景。沿用 MySQL、精简回放、个体经历、对话分析、增量上下文与十日反思。

## 实验问题

一个已经建立的社会，在固定王税、地租与粮食减产之间怎样选择？关注家庭储粮、实际交付、拒绝、承诺兑现、结盟、暴力与王室响应。拒绝交粮、停工、攻击等均由普通动作组成。王室的“叛乱认定”是外部制度反应，不能直接当作农民起义的科学标签。

本地初始 31 人：1 位被承认的领主、5 位职业武装随从、1 位村长、24 位农民。农民组成 6 户，每户父母与两个成年子女，预置亲属、邻里互助和田界纠纷。身份、惯例、地租、动机和人物关系写入个人初始上下文。物理规则不检查领主、村长或农民身份。

`Agent.residence` 保存熟悉住所、日常储藏与田条，作为确定性劳动路线的初始知识。钥匙访问检查实际背包：转交钥匙、破坏门锁、拿走死亡者掉落钥匙都可以改变物理访问能力。`warrantSubject` 是地图外国王出使文书中要探访的具体人物 ID，只用于使者核实，不能赋予本地行动权限。

## 固定地图与画面

24×24 格，单格约 15 米，是小屋和田条交互入口的尺度。生产田条代表外围耕作带；其实际生产覆盖面积不等于画面中一格的几何面积。地图和月度生产周期是领地政治实验的空间与时间压缩，不是中世纪小麦实测生长模型。

- 西侧 `(0,10)` 为王室道路出口，贡粮在这里实际离开领地。
- 中央 `(8..11,10..11)` 是公共广场，设公共井与告示板。
- 六户住宅在 `(5,8)、(8,8)、(11,8)、(5,13)、(8,13)、(11,13)`，每户独立粮箱和钥匙。
- 南侧 48 条固定农田，每位农民熟悉两条；各户粮食先进入家庭储藏。
- `(12,12)` 是公开工棚和材料箱。
- 东北为石墙庄园，入口 `(15,10)`，大厅 `(18,7)` 内设粮仓 `keep-store`，两者同格。

地图使用 Canvas 2D 等距投影，按纵深排列建筑、树木和人物，包含石墙、屋顶、田垄、作物阶段、阴影和岛台边缘。支持高 DPI、拖动、缩放、网格、点击地块和居民查看。面板展示实际库存、田间劳动和王室账簿；观察者的全局面板不进入 Agent 视野。

## 粮食与数值账

谷物每 kg 3400 kcal，每个成年人每日需求 2500 kcal，因此一人日粮为 `2500/3400 = 0.735294 kg`。磨粉、煮粥和家庭取水并入日常生存，干粮在本实验窗口按稳定储粮处理。只有农田增加本地食品；旧生态采集、捕鱼、狩猎、畜牧、旧作物和旧制作动作在领地场景被拒绝。

| 项目 | 正常收成 | 默认灾后 |
|---|---:|---:|
| 潜在月产 | 1800 人日 / 1323.53 kg | 900 人日 / 661.76 kg |
| 31 人每月消耗 | 930 人日 / 683.82 kg | 同左 |
| 24 人农户需求 | 720 人日 | 同左 |
| 按 50% 地租保留在农户 | 900 人日 | 450 人日 |
| 收入领主体系（若实际缴齐） | 900 人日 | 450 人日 |
| 王税 | 固定 450 人日 | 固定 450 人日 |
| 7 人领主体系需求 | 210 人日 | 同左 |

这些税后数字是假定人们真的交粮的预算推演。引擎不会按表自动转移任何粮食。地租只是提示词中的惯例；国王税额由外部 FSM 执行。

每条田每月需 1800 人分钟（30 人小时），产出 `1800/48=37.5` 人日净粮。48 条田合计 1440 人小时，24 个农民平均每月 60 小时，约每日 2 小时。默认日程逐步完成两条田的劳动额度，余下时间可用于运输与社交；每次收割最多 12 kg，消耗 120 分钟。种粮、加工损耗包含在净产量基准中，不会再额外扣除。

月底新增成熟粮：`田条净产量 × 灾害倍率 × min(实际劳动/所需劳动,1)`。第 30、60、90、120、150 天日末成熟，次日起收割，未完成劳动直接减产；地上成熟粮和已入仓粮分开统计。停工对下一轮收成有真实后果。

默认第 10 天灾害生效，影响下一次月底结算；只有附近看到农田的居民得到作物损伤信息。每户初始 35 天储粮，普通居民另有 2 天随身口粮；领主最多携带10天口粮（低负重配置按装备后的空间缩减），明确知道粮仓位置、取粮动作及六人每日约4.41kg的正常饮食开销。初始缓冲让饥荒和征税之间留有交涉时间。季节画面和日历沿用旧设施，领地粮食不再叠加旧生态的温度、积温和季节产量公式。

实验配置可调：地租比例、每期王税（人日粮）、灾害日（0 关闭）、灾后倍率、拖欠时间限制和王军人数；上下文窗口、模型预算、AP 和背包等仍可设置。地图、区域数和初始人口固定为此场景布局。

## 日常执行与自主目标

默认规则只做：食用随身粮 → 回熟悉的储藏取口粮 → 照管熟悉田条/收割 → 收获搬回储藏 → 到广场等待自主交流。没有未知食物的全图搜索，也不代替人交税。

LLM 下达目标后，执行器按目标自动导航、分批搬运，并根据实际库存、负重、门锁和剩余劳动检查。交付计划可消耗家庭储粮，这个决定须由 LLM 明确授权。目标执行受阻会成为下一次上下文的反馈。

```json
{"intent":"暂停农活，要求村长商议减税","goal":{"skill":"estate","op":"rest","expires":20}}
{"intent":"向村长交粮","goal":{"skill":"estate","op":"give","targetId":7,"quantity":20,"expires":35}}
{"intent":"履行王税","goal":{"skill":"estate","op":"tribute","quantity":330.8824,"expires":35}}
{"intent":"改种另一条田","goal":{"skill":"estate","op":"work","id":"plot-12","expires":30}}
{"intent":"制作铁矛","goal":{"skill":"estate","op":"craft","recipe":"iron_spear","expires":15}}
{"intent":"破开庄园入口","goal":{"skill":"estate","op":"break_lock","id":"15,10","expires":45}}
```

`estate` 工序：work、withdraw、deposit、give、tribute、craft、break_lock、unlock、lock、rest、guard。目标支持坐标导航、约见和明确攻击。收税依靠请求与交付；村长不能凭称号远程划走农民粮食。`guard` 为驻守，受到攻击者会自卫反击；群体结盟和主动攻击对象仍须通过 Agent 自主决策建立。角色不会因长期没聊天而自动扣血，此实验的主要生命压力来自粮食和战斗。

工棚使用独立简化配方：铁矛、铁剑、木皮盾、皮甲、铁镰、木板、铁刀；初始有有限的铁、木、皮革和绳。制作从公开材料箱实际备料，消耗 60–240 分钟。初始武装随从持铁剑、锁子甲和盾，农户有铁镰；领主大厅提供伤害减免。装备以实际持有为准。门可破坏，城墙本体是固定不可通行地形。

## 王室与使者

首次王税期限 D35，之后每 30 天一期。王室只核对实收与欠额：按期足额则继续等待；不足立即记为欠税并派使者催缴，无宽限、延期或领地因素豁免。拖欠时间限制默认 7 天；连续欠税严格超过 14 天，或使者根据亲见证据自行认定叛乱并返回报告，生成默认 10 人王军。D35 欠税且一直未清偿时，D49 不出兵、D50 出兵。部分偿付及新一期税款不会重置连续欠税日期，清偿全部欠款后才清除计时。预缴和补缴进入同一本账。王军由地图外王室供应军粮，日结恢复饱食度，战斗伤害与阵亡仍按物理规则结算。

使者仅在欠税后作为地图内人物进入，具有询问、观察和返回日程；LLM 模式下可以进行社交和自主访问。观察受封者尸体时保存亲见报告；使者可提交 `estate report_rebellion`，以 `text` 说明本人判断；返回道路出口后王室才收到叛乱报告。单纯目击尸体不会自动认定叛乱。传闻标记为传闻，不直接确认死因或凶手。使者死亡不会把脑中信息瞬间传回国王。王军按距离选择可达的活着居民，追击、破门并攻击同格目标，所有领地居民均为目标。王军和使者不在目标集合中；资源征缴不再是王军任务。目标位置只供王军确定性执行器使用，不进入居民LLM上下文。

系统只按欠税超时自动认定抗税，领主死亡由使者自主判断并报告；报告保留来源和判断依据。出兵后不因补缴税款撤销镇压。

## 上下文、存储与代码边界

场景共享规则在 system prefix，共知地图放在共享规则之后、个人后缀之前；人物经历、家庭和熟悉田放在固定个人后缀。活动尾部只追加当次附近农田、可打开储藏和现场事件。隐藏库存、王室全账簿和未亲见的全球灾害不进入 Agent 活动上下文。默认 100k 窗口、长期外部记忆、固定知识保护与十日反思。

主要入口：

- `frontend/src/manor/world.ts`：布局、人口、家庭、初始经历、经济配置。
- `frontend/src/manor/engine.ts`：实物操作、月度农业、国王与外来人物。
- `frontend/src/manor/controller.ts`：固定田和住宅日程、高层目标执行与最短路径。
- `backend/app/manor_prompt.py`：场景共享提示词。
- `frontend/src/ui/ManorMap.tsx`、`ManorDashboard.tsx`：等距地图与领地面板。
- `scripts/validate-manor.ts`：离线跨月规则集成验证，零模型请求。

运行 `npx tsx scripts/validate-manor.ts 120` 可验证 120 天物理流程，报告写入 `artifacts/manor-validation/report.json`。此规则基线不会自行交税，因此出兵是预期结果，不能用它判断 LLM 是否会反抗。行为实验建议比较正常收成/减产、低税/高税四组，并重复多个随机种子。


## 已完成验证（2026-09-11）

- 修复后的 60 天零模型规则基线：70,495 个启动/完成/日末事件，D30 成熟 661.76kg，D60 成熟 632.35kg；实际劳动减少会反映到下一次收成。
- D35 催缴、D42 出兵；D53 使者亲见受封者尸体后返回并报告。此基线没有自主交税和结盟策略，因此不能据此推断 LLM 的社会行为。
- 规则基线期末 22 名初始居民存活，另有外来人员。记录到89次失效动作，来自延时执行期间目标移动、目标死亡、同伴已破门或共享库存变化；均通过实际状态校验拒绝，没有田间劳动卡死错误。
- 补充了空粮箱返回循环、制作备料保留目标、普通人拿钥匙开仓、实际交付与回放、王税欠缴阈值、使者信息边界、刻字与停工等回归检查。
- 浏览器验证了等距地图、缩放、点击、税率与灾害日设置；另保存3天脚本演示到MySQL，未发起付费模型调用。

地图右侧默认显示按居民筛选的决策历史，按启动事件序号倒序分页，固定查询边界防止回放看到未来。点击可展开原子动作、私有备注，并打开原有完整上下文窗口。服务端使用 `(experiment, actor_id, type, seq)` 索引，每页返回至多20条决策；只看模型调用时，每批最多扫描200条并继续游标翻页。

## 导航回执与自主日程（2026-09-11）

日志中的罗兰曾在 D2 E1100 到达 `(20,5)`，随后日常执行器将他带回广场。旧 `arrived` 状态未失效，让后续反思把成功导航误记成路径不可达。导航现在记录目的地、到达日，离开即清除到达状态；庄园中抵达后默认停留 600 劳动分钟。新目标立即接管，`movement.stayMinutes` 可调整或解除停留。成功取放、交付和制作等保留 `lastTaskResult` 回执，进入增量上下文和事件回放。

未自主配置日程时仅启用 `{mode: "custom", eat: true}`，Agent 在首次决策自行提交其他自动任务的 `custom` 配置，重设时显式保留 `eat: true`；已有显式配置继续保留。`self.dailyRoutine` 展示当前实际执行的日程、步骤顺序、触发阈值、储藏、田条和空闲目的地。Agent 可提交：

- `dailyRoutine: {mode: "default"}`：兼容已有 Agent 主动选择的旧预设（吃随身粮、领口粮、存余粮、照管熟悉田条，最后去广场）；新 Agent 不自动启用。
- `dailyRoutine: {mode: "off"}`：关闭自动日程，包括吃随身粮；显式目标仍执行。
- `dailyRoutine: {mode: "custom", eat: true, fetchFood: true, storeSurplus: false, farm: false, storeId: "keep-store", reserveDays: 3, plots: [], idleAt: [18,7]}`：完整替换日程；指定取粮储藏、余粮保留量、劳动田条、空闲目的地。省略布尔项为 false，省略田条为空，省略 idleAt 为 null（原地），储藏默认为熟悉储藏，保留量默认 2 日。

`clearGoal: true` 取消旧目标，可与新目标一并提交。日程配置跨日保留；显式目标优先于日程移动、存取与农活，自动进食开启时先吃随身粮。原地停留优先于日程移动。自定义储藏仍检查实物钥匙、库存与容量。该配置针对当前领地执行器；旧生态场景保持原执行方式。

大声说话仍耗 2 AP（240 分钟），同一区域五格内（含斜向）的活人可听见，死亡或已离场人物除外。普通聊天与公开发言保持一格；并行调度把五格内潜在听众列为冲突，避免使用漏掉刚发生喊话的预取上下文。

定向验证涵盖：穿过庄园门到粮仓及到达停留、无钥匙受阻、离开后状态清理、成功取粮回执、日程关闭/替换/恢复、五格喊话边界及事件回放。


王室政策更新：领主提示明确要求收获后再向农户收税；王室使者无权给予宽限、延期或认可欠税借口。配置界面将原“宽限天数”显示为“拖欠时间限制”；为兼容存档，底层键名仍为 `graceDays`。国王以 `overdueSince` 记录首次连续欠税日，旧存档缺失此字段时采用最近到期日，不再使用旧 `deadline` 作为宽限。税款不足触发催缴，出兵严格按上述两个条件执行，单纯欠税不伪造使者叛乱报告。

自动进食按实际热量缺口补到 100 饱食度（5000 kcal），按先存入先食用及批次品质计算食量；随身粮不足则吃完，已饱不吃。


## 阻塞与分批执行

资源动作的quantity表示剩余任务总量。执行器按当前源库存、本人负重和接收方容量分批完成；库存不足、上锁或容量不足时转为等待并显示goalBlocked。实际执行中的竞争失败保存物理条件签名，条件未变化时不重复尝试；新目标可清除阻塞。同一失败不应通过反复消耗AP继续发生。领地日程的普通取粮、显式任务和交付统一使用此检查。已有目标与自动取粮的优先级仍按日程配置执行。

并发架构另见 [Agent异步执行协议](AGENT_ASYNC_EXECUTION_PROTOCOL.md)，该协议为下一阶段设计。


## 个人账簿与默认实验参数

新实验给领主和村长各一本 `personal_ledger`（1kg，实物 ID 为 `ledger-人物ID`）。账簿复用铭文记录，每条保留作者、日期、事件序号与文本；记账由 Agent 自己决定，物理收支仍以成功操作回执为准。

- `goal: {skill: "estate", op: "write_ledger", id: "ledger-1", text: "实收谷物3kg；另5kg尚待交付", expires: 30}`：耗60分钟，追加1–240字，持有人原地书写，完成后结束目标。
- `goal: {skill: "estate", op: "show_ledger", id: "ledger-1", targetId: 7, expires: 30}`：走近目标至一格内，耗24分钟，只将当前条目展示给指定活人并记录其阅读经历。后来追加的内容需再次展示。

只有实际持有整本账簿的人可自动阅读和书写，与角色身份无关。账簿可以整本交付、存放、拾取；地面或仓储中的账簿只显示物品，不暴露正文。原持有人和已获展示者保留此前阅读的记忆。邻人能观察书写/展示行为，但不会由动作广播得到正文。账簿没有自动法律效力，内容仍可能不实。

铭文页面增加“个人账簿”载体筛选与账簿记录计数，可按作者、持有人和时间查询；跟随所选世界快照回放。现有存档兼容缺少账簿字段的物品。

默认上下文窗口为100,000 tokens，普通决策、深度反思、压缩与新闻均不向模型发送输出截断参数；上下文和调用预算中的预估输出余量只用于发起请求前的检查，实际输出用量照实记录。实验默认150天，歉收从第40天启用，之后月度结算按减产倍率生成粮食：默认首月第30天正常收成，第60天起减产。显式设置与已保存实验配置保留；初始账簿只随新世界生成。
