# Agent 访谈

连续实验的「Agent 访谈」页面用于检查角色对世界、记忆和决策的理解。选择任意角色（包括死亡、离场和王军角色），然后新建会话即可提问。同一角色可以建立多个独立会话。URL 中的 `agent` 参数定位角色，浏览器保留该角色最近选择的会话。

## 认知与会话边界

新会话复制 `continuous_contexts` 中该角色实际保留的 prefix 和 tail，并冻结为会话种子。访谈模式保留性格与已有认知，要求区分亲历、传闻、推测和用户新告知的信息。不会向角色额外提供全知世界状态。冻结时间是创建会话时的世界时间；「末次保留观察」是角色实际上下文中最后一次观察，死亡角色二者可能相差很大。经过上下文压缩的历史仍以实际保留版本为准。

没有历史 LLM 上下文的角色使用其个人背景创建会话，页面明确标注这一限制；这种回答不能作为真实历史记忆的证据。访谈是事后自述，不能代替原始决策日志进行因果验证。

聊天不会写回实验上下文、执行游戏动作、推进时间或复活角色。新会话之间完全隔离；清空记录会保留原会话的冻结种子，若要使用更新后的角色认知，请新建会话。

## 交互

- Enter 发送，Shift+Enter 换行。
- Reasoning 开关应用于下一次发送或重试。模型启用对应思考模式；服务端将模型 API 返回的 `reasoning_content` 完整写入 LONGTEXT 字段，页面在回答上方以可折叠的「思考过程」展示原文，默认展开。没有返回该字段时明确提示；旧回答只存过摘要，需重试才能生成思考原文。
- 修改输入会替换该轮与之后的消息；重试使用原输入和当前 Reasoning 设置，执行相同的替换规则。
- 生成失败保留错误，允许手动重试；失败消息不会成为后续模型的对话历史。
- 清空记录删除该会话所有轮次，删除会话同时删除其冻结上下文。生成中的会话也可清空或删除，迟到的结果不能恢复已删除内容。
- 不设截断性输出 token 上限。使用创建时实验配置的上下文窗口，接近窗口上限时拒绝新输入并保留历史，提示另开会话。

## 存储与执行

MySQL 独立表 `agent_chat_sessions` 保存角色、标题、压缩后的冻结种子、元数据和版本；`agent_chat_turns` 保存用户输入、回答、思考原文、Reasoning 设置、错误和 token 用量。实验表仅被读取。

前端 `/chat-api/runs/{run}/chats` 直接代理至 Python 网关的 `/runs/{run}/chats`。生成由后台异步任务执行，独立并发限制为 2；模型请求使用流式传输，前端通过 `/chats/{sid}/stream` SSE 订阅，约 100ms 合并推送一次思考／回答增量，不阻塞模拟写入服务。后台保留活跃输出，每两秒写一次 MySQL 检查点，结束或失败时保存最终内容；不逐 token 写库。每个会话以 revision 和 busy 请求 ID 防止重复提交、并发覆盖和已删除数据复活。进程重启将未完成的轮次标为可重试错误。

- `npm run build`：通过。
- `artifacts/chat/interactions-check.mjs`：浏览器通过深链接、刷新、发送、编辑截断、重试与 Reasoning、会话切换、清空和删除；使用 API mock，不消耗模型调用。
- 对真实实验 `continuous-1789123107617-75b7fc` 的已死亡 6 号角色完成一次 Reasoning 访谈，真实回答显示成功，会话已保留。桌面和 390px 移动视口检查通过。

更新：旧会话的冻结认知保持原样；发送时仅将旧的访谈输出格式转换为自然语言回答格式，直接输出文本以支持增量渲染。历史思考原文用于展示，不回填后续对话输入。

## 流式恢复

SSE 连接先发送数据库快照，再以轮次 ID 和 UTF-16 字符偏移推送增量；重连时重新发送快照并校准活跃输出，防止重复追加和表情字符错位。连接中断会自动重连；刷新页面或切换会话只关闭订阅，后台生成继续。进程异常退出后，未完成回答标为错误，保留最近检查点，最多损失尚未保存的约两秒输出。上游流提前结束时保留已收到的文本并显示错误，允许重试。删除会话后迟到内容不会写回。

页面分别显示思考和回答增量；跟随底部滚动，用户向上阅读时停止自动跟随。`artifacts/chat/stream-check.mjs` 使用真实 SSE 测试部分输出、刷新、断线重连与最终状态。

真实模型流式验证：已死亡 6 号角色的新会话在约 2.5 秒产生第一段增量，约 4.3 秒完成，共 15 次增量推送。结果保存在 `artifacts/chat/real-stream-result.json`，会话保留供查看。
