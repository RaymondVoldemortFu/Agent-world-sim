# 连续实验第45天崩溃与渲染耗电修复

实验：`continuous-1789123107617-75b7fc`。故障边界 E184905，游戏时间 3812888084.4280787 ms（第45天03:08）。

## 崩溃原因与复现

33号王室使者的 `home=exit`，exit 是道路出口，存在于地点表，不存在于储藏表。观察生成器仍把它写成“家庭储藏exit”。使者据此开启 `routine.fetch=true`，随身粮少于两日时规则生成 `supply exit`。

显式 supply 任务检查过目标必须是储藏，但自动日程只检查显式 supplyStore；省略 supplyStore 时会使用 home。动作执行阶段把 `stores.find(...)!` 当作一定存在，随后 `accessible(undefined, agent)` 读取 lock 抛出异常。单个角色的无效任务停止了全世界推进。

使用只读导出的实际存档副本可以稳定复现，堆栈为 `accessible → ContinuousEngine.ensureAction → advance`。存档记录使者口粮0.98975kg、fetch=true，任务take exit，与截图一致。

## 修复

- 设置 fetch 时校验最终生效的储藏（supplyStore 或 home），缺少真实储藏则返回具体错误；在修改角色计划前完成校验。
- 自动任务执行时再次检查目标储藏是否存在。旧存档中的无效配置只阻塞该角色并提供原因，其他角色与世界时钟继续运行。
- 动态观察明确区分驻地/出口和家庭粮仓；没有家庭粮仓时提示协商口粮或指定真实 supplyStore。现有实验下一次观察即可收到，不依赖重建固定 prefix。
- 日程展示不再把不存在的储藏标成“补粮仓”。没有给使者生成额外粮食或虚构存储。

## 渲染耗电问题

原地图仅在 `status !== running` 时跳过不变画面。服务器故障后已提交世界仍标记 running，虽然时间冻结，前端依然逐帧更新角色、DOM与WebGL。渲染循环也未显式处理页面隐藏，且初始化要求 high-performance GPU。

现改为按实际画面状态跳过重复帧，与实验状态字段解耦。document.hidden 时取消动画循环，重新可见时恢复；前台运行默认30FPS预算，键盘与镜头变化时最多60FPS。GPU偏好使用default。服务端游戏时间和决策频率不受前端绘制预算影响。

渲染器增加 `data-rendered-frames` 便于测量。独立浏览器回归用32人场景模拟“running但不再收到新状态”，确认稳定后1秒新增绘制为0；模拟隐藏时世界仍更新，1秒新增绘制也为0；恢复可见后继续绘制。实时场景检查有新帧且两秒不超过65帧。这验证无效渲染被消除，不代表已测量电脑整机温度或真实硬件的持续帧率。
