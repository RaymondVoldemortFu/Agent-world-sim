# 生态产业与混合 Agent：实现说明

规则版本：`eco-2.0.0`。与 `HYBRID_AGENT_ARCHITECTURE.md`、`PREHISTORIC_ECONOMY_DESIGN.md` 配套。代码、实际运行记录和验证结果是当前行为的依据；设计稿里的历史范围与候选参数不等于已经校准过的历史模拟。

## 启动与查看

```sh
npm run dev
npx tsx scripts/simulate.ts --mode llm \
  --config docs/data/eco-hybrid-100day-config.json \
  --out artifacts/my-ecology-experiment --concurrency 8
npx tsx scripts/verify-run.ts artifacts/my-ecology-experiment
```

浏览器 `http://127.0.0.1:5173/?experiment=my-ecology-experiment`。配置页可选择采集者或农业定居开局、初始年内日、每天模型请求上限。Web UI 保留开始新实验、中断、继续、历史回放和纪事检索。历史存档按自己的规则读取。

CLI 和 UI 的新实验默认采用生态规则。`createWorld()` 这一底层函数保留简化规则默认值，供已有程序和历史测试使用；调用方用 `worldModel: "ecology"` 显式启用新系统。真实模型凭据仅由本地 Python 后端读取。

## Agent 与运行时

- `brain/controller.ts` 只接收 `EcoObservation`，不接收完整 World。观察包含九宫格当前事实、自己的物品和认知、带日期的记忆、可见活人及尸体。远处角色的背包、计划、记忆不进入上下文。
- 规则优先补水、进食、寻找口粮、处理背包中的高风险食物，再执行长期目标。孤单时可以寻找活人，真实说话内容和合作同意由模型决定。
- 长期目标包括制作、建造、农耕、送货、会合、繁衍、探索、改造和畜养。制作会准备已知前置工艺；材料采办记录工作地点，搬运与施工可跨天。多人可贡献同一工序与工程，系统不预设他们有共同产权或共同目标。
- 高层目标还包括狩猎、全力观察、向指定角色学习工艺、维修与明确攻击。狩猎副产物提供骨、皮、脂和羽毛，支持弓箭等后续工艺；控制器会把有日期的观察结果纳入个人地点记忆。
- 模型按新提议、新交流、孤单、任务失败、计划到期和阶段回顾唤醒。输出目标、真实讲话、明确提案处理和私有判断。常规原子动作不会请求模型。
- 普通聊天 24 分钟，喊话和全力观察 240 分钟。成功丢弃为零分钟，销毁手上物品；转移到地面保留物品。默认每日 600 主动分钟，显示为 5 AP。移动由地形、负重与道路计算。
- 行动开始扣除时间，完成时才产生物理效果。运行器按下一空闲角色与下一完成事件的时间调度；空间独立角色可并行请求模型，结果按确定顺序提交。零时间动作有单独的提交边界。
- 每人日请求上限默认 2、配置硬上限 3，包含重试与格式修复。Token 配额和全局费用预算按返回用量进行后续调用准入；单次已发出的请求可能跨过 Token 阈值。耗尽模型预算后用规则继续，并记录降级。
- 每次模型请求、修复、技术失败保留在 decision record。规则和模型动作分别计数。开始事件与完成事件引用同一决策来源；私有判断标记 inferred，阶段性整理进入个人主张。
- 存档包含任务、已投入材料、等待时间、角色忙碌状态、计划和认知。CLI 与 Worker 使用同一控制器和物理引擎。

## 生态、季节和区域

一年 365 天，春 60–151、夏 152–243、秋 244–334，其余为冬。日温、降雨、日长和年度干旱因子由日历与种子产生。

默认三个相连的 15×15 区域：河谷、铜山、锡岭。每格 250 m × 250 m，即 6.25 ha。跨区需要先走到边界，再支付旅程时间、饮水与体内能量。矿产差异使铜锡供应与运输存在地域约束。地图有河流和浅滩；深水需要舟筏或桥。

六类生态地形具有不同野生食物年产、森林物料、地表水与矿藏。植物按季节补充可采生物量，同时有站立损失；鱼类与猎物采用有限容量的 logistic 更新；森林按多年尺度生长；矿藏只减不增。种地、建造占用土地后，相应野生生境减少。

土壤状态包含水分、有效氮、有机质与侵蚀。降雨、蒸发、引水、施肥、作物和坡度分别影响状态。当前是单格水量与简化养分模型，并非连续流域水动力或完整磷钾模型。灌溉从实际相邻水源扣水，不能凭空补水。

## 产业系统

实际目录由 `ecology/catalog.ts` 定义，UI 可展开查看每条工艺的输入 kg、输出 kg、劳动分钟、等待天数、工具能力与设施条件。

技术分支包括石片、手斧、磨制与柄装工具、掘棒、矛弓、骨针、弓钻、纤维浸沤、绳网筐、皮革服装、纱线织布、磨粮炊食、鱼肉干制、制陶、木炭、铜锡与青铜、块炼铁、锻造和金属废料再加工，以及独木舟、木筏、拖橇、轮轴与牛车。

建筑包括营棚、泥屋、共居屋、炉灶、烟棚、两级粮仓、工棚织架、陶窑、炭堆场、铜锡炉、块炼炉、锻工棚、畜圈草棚、井、简桥码头。建筑有占地、材料、累计劳动、状况、维护和实际仓储容量。作物包括春谷、秋谷、豆、亚麻、牧草。

工序在启动时检查条件、取走真实材料并独立保存。之后多人投入劳动，等待干燥、浸沤或炉次；看护不足会影响品质。完成只结算一次，产物在工作地点地面。取消按已加工比例退回未加工部分，损耗进入账目。工具按能力工作、累积磨损并可耗材修补；碎片不会取得完整车辆的负重能力。

农田以 0.25 ha 子田记录备地、种子、播种劳动、生长积温、照料、成熟待收和收割劳动。谷物基准毛产 750 kg/ha、豆类 500 kg/ha；产量受土壤、水分与照料修正。播种先扣实际种子并持久化，后续补足劳动不会重复扣种。收获不会直接生成可吃到永远的“农田食物”。

畜群需要草料与水，冬季依赖库存。饥饿影响健康和繁殖；乳产限定泌乳季节，每天最多获取一次。屠宰减少真实头数。当前畜群用群体参数表达，未展开每只动物的年龄、遗传和个体妊娠状态。

## 数值与守恒边界

- 食物批次含 kg、热量密度、水分、质量、风险、来源与日期。转移不刷新保质期。腐败风险与剩余热量分开；温度和仓储改变损耗。
- 干燥食物在参考 15°C 的良好仓储条件下，180 天质量保留率约 94%；裸放约 75%。实时模型按日损耗，不在收获时重复扣同一仓储比例。
- 参考河谷植物年度潜在能量按设计的 7,500 FD 分配到实际生境；地区面积缩放，初始人口变化不会自动降低资源。鱼和猎物显示的是现存生物量，不能把库存当成年产量。
- 10 kg 含铁 45% 的矿，经焙烧、块炼和锻炼，标准链得到约 1.296 kg 熟铁；16 + 4 kg 木炭对应 80 kg 干木。铜锡按配方品位和收得率结算。
- 通用配方校验要求输出质量不超过输入、食品输出能量不超过食品输入。隐含烟气、蒸发水、碎屑等差额进入损耗；这不是完整的元素化学反应模拟。
- 图上的 1 FD = 2,500 kcal。20 人实验初始为成年人，需求约 20 FD/天；设计稿的“16 成人 + 4 儿童”参考人口是另一种压力口径。
- 地方生态、获取劳动、模型合作意愿、储藏损耗都有独立影响。参数属于可复现实验初值，尚不能拿一轮 100 天运行宣称历史真实性或社会结构必然出现。

## 验证与实验

`frontend/tests/ecology.test.ts` 验证完整配方目录、标准材料投入下的各工序、跨天加工、取消与完成约束、真实种子与播种、季节、批次储存、空间隐私、明确繁衍同意、尸体与喊话、零调用预算、零时间调度和事件回放。遗留的模型、调度、引擎、感知测试用于检查兼容性。

UI 测试覆盖区域切换、居民状态、工艺目录、配置、新实验和中断/继续。构建执行 TypeScript 检查。

正式实验配置：`docs/data/eco-hybrid-100day-config.json`。100 天跨越年内 180–279，覆盖夏季、秋收与秋播；不等于完整年度农业或一代人的人口检验。实验结果在结束后另写报告，区分已实现机制与本轮实际发生的行为。

正式实验曾保存检查点以补齐上述高层动作与模型尝试配额核算，然后从同一存档继续。代码变化边界记录在 `implementation.jsonl`，最终报告按这次连续实验解释，不能视为同一冻结代码版本的整轮对照实验。
