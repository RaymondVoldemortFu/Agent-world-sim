## 结论

近期折返由确定性的任务生命周期与自动日程冲突造成。路径确实到达庄园大厅；`navigate` 完成时被删除，1游戏秒后 `idleAt=plaza` 开始自动返回广场。下一次 LLM 思考在数小时之后，错过了在大厅观察与继续执行的机会。最小复现完全不调用 LLM、不产生并行请求，也能得到同一结果；这些折返不能归因于异步回复乱序或 A* 寻路失败。

## 叠加的问题

1. **抵达没有交回决策权。** `engine.ts` 的 navigate 分支删除任务，只等待1秒；自动日程马上接管。`thinking()` 设置12游戏小时后的下一次思考，`thought()` 保证至少再隔6小时；到达不会提前触发。单纯唤醒 LLM 仍不够，因为等待网络期间规则也会立即把人带走。
2. **意图文本与实际计划不一致。** 雨果多次说“这次改成rest，抵达后停留”，实际输出仍是 `navigate` 或 `supply`，并反复保留 `idleAt=plaza`。观察的“日程扩展”确实向他显示了“闲暇去处=plaza”，并非字段完全缺失，但没有解释下一次自动折返的因果关系。
3. **speech 与 task 同时启动，不是到达后说话。** E47789 的“领主！管家雨果求见……”于D21 16:27在途中说完，听众不含 #1；到大厅是18:12。E48846、E49431、E51572 的实际听众为空。当前动作结构无法表达“走到大厅→等领主在可听范围→再说话”的连续步骤。
4. **日志来源标识不足。** `walk:plaza` 是自动日程生成，但其 `action.auto=false`，因为 walk/start 没有传递 routine 来源。这让用户及 Agent 都难以区分谁发起了折返。
5. **管家寄给领主的信要自己再审一次。** 他寄给领主的两封信，一封由自己寄出又交回自己持有、处于待审状态，另一封仍在途，尚无已转交记录。他因此将写信理解成“自寄自审没有意义”。这是另一个可用性问题，与本次导航折返分开。

## 最小复现

脚本：`artifacts/diagnostics/reproduce-agent3-navigation.ts`。让3号已经站在大厅，再推进1001游戏毫秒：

| 设置 | 结果 |
| --- | --- |
| navigate大厅 + idleAt=plaza | 1000ms后开始返回广场 |
| navigate大厅 + idleAt=keep-store | 原地休息 |
| rest大厅 + idleAt=plaza | 保留显式rest任务，原地休息 |

这说明即时缓解可以是持续的 `rest/guard keep-store`，或将 `idleAt` 改成大厅；本次仅验证，没有代替 Agent 修改计划。

## 建议修复方向

- 显式任务完成后进入等待下一步决策的阶段，保留到达位置，触发一次按任务版本去重的事件驱动思考；在该阶段暂停闲暇移动，继续进食等生存行为。
- 增加顺序任务或到达后动作，让“去某处再向某人讲话”可以被机器执行；依然在实际发声时核验听众距离。
- 将规则生成动作明确标成 routine，并把“为何返回、由哪个配置触发”写入反馈；观察解释 `idleAt` 的具体后果。
- 独立处理管家自己寄出的信，将他发信本身视为已审，而非回到自己信箱等待二次操作。

以上为调查时的建议。后续已按用户要求实施下述导航控制修改，其余建议仍待处理。

## 已实施：navigate 接管移动

接受 `navigate` 时立即中断当前动作，关闭 `fetch`、`work`，清除 `depositStore` 和 `idleAt`；保留自动进食及其余配置。即使同一导航计划重复提交旧 routine，其中的自动移动配置也不会生效。抵达后留在原地，后续显式提交 routine 才能恢复自动任务。

共享规则、每次观察及 `routine_interrupted` 动作反馈均明确说明此行为。上述最小复现表记录修复前结果；修复后的回归测试确认导航抵达后经过四分之一游戏日仍留在大厅，并覆盖自动取粮预留释放、进食开关保留、后续恢复 routine、无效坐标不修改状态与事件回放一致性。20项相关测试及前端构建通过。
