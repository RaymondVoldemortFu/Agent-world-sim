# MySQL 精简动作与逐事件回放

实现日期：2026-09-10。后台实验默认使用 MySQL，保留每个原子事件的状态回放能力。TypeScript 模拟引擎继续负责世界规则和决策执行；Python 后端负责存储、事务、查询和回放读取。

## 数据结构与保留范围

每个事件的序号保持不变。数据库将检索用的事件摘要与回放用的状态增量分开保存：

| 数据 | 保存形式 | 用途 |
| --- | --- | --- |
| 动作摘要 | 事件序号、日期、角色、动作参数、结果、决策引用；社交保留对话正文 | 世界纪事检索、对话分析、决策查看 |
| 状态增量 | 路径与变更值的短数组，zlib 压缩 | 每个原子事件的精确回放 |
| 当前检查点 | 完整世界与累计运行时间，压缩二进制 | 崩溃恢复、继续实验 |
| 周期快照 | 初始状态、每个日结状态 | 回放从最近快照开始 |
| 个体时间统计 | 角色 × 日期 × 动作 × 决策来源的分钟、开始/完成/失败次数 | 统计页直接查询 |
| 决策记录 | 结构化动作与意图；实际模型调用的输入、回复、尝试和用量 | 解释行为与成本审计 |
| 未提交模型响应 | 独立持久化记录，提交事务内删除 | 暂停、重启和故障恢复 |
| 经历索引 | 社交、产业、反思等经历 | 按角色、日期、来源和关键词查询 |

规则动作不重复保存完整观察上下文，基础事件的文字摘要简化为角色和动作。世界状态中影响行为的记忆、私有认知、任务、物品批次等仍通过增量完整保留。实际调用模型的提示和回复保留；混合模型使用真正发送给模型的精简上下文。

时间统计采用**分配给动作的分钟数**，在动作开始时计入，并在完成时更新结果。包含进行中的劳动，不表示已经耗完的现实时间。旧 AP 模型按 1 AP = 120 分钟换算；死亡造成 AP 归零不会被当成额外劳动。按开始日记账；历史回放的统计页只统计该时间点之前已完成的模拟日。

## 增量协议

压缩前的数据示例：

```json
[
  ["set", ["seq"], 123],
  ["set", ["agents", 2, "hunger"], 80],
  ["queue", ["agents", 2, "memories"], [1, [{"id":"123:3:0","content":"进食"}]]],
  ["tail", ["agents"], [20, [{"id":21}]]],
  ["del", ["agents", 2, "pregnancy"], null],
  ["order", ["agents", 2, "brain", "goal"], ["skill", "x", "y", "expires"]]
]
```

示例中的角色和记忆省略了其他字段。`set` 替换字段，`del` 删除字段，`queue` 丢掉队首并追加新条目，`tail` 截断数组尾部并追加，`order` 保留对象键顺序。最后一项用于兼容旧版依赖 `JSON.stringify` 的状态哈希。回放直接应用存储的增量，不调用模型，也不重新执行当前版本的物理规则。

## 提交与查询

- 累积最多 50 个事件；日结、模型外部调用之前、正常中断和结束时提交。规则连续执行期间的故障最多回退到上一批提交，可重复计算。
- 一个事务同时写动作、增量、决策、时间统计、检查点，并删除对应未提交响应。异常全部回滚。
- 以预期事件序号和目标检查点防止乱序写入；同一批提交在网络响应丢失后可以幂等重试。
- 模型请求前保存未提交记录，每次尝试后保存结果；响应已持久化的重启无需再请求。外部模型返回与本地持久化之间若进程硬崩溃，仍可能重试该调用。
- MySQL 使用按实验与序号、事件类型、角色和经历游标建立的索引。世界纪事和经历都采用游标分页。任意中英文子串检索在该实验的精简摘要上进行，不读取完整状态或原始大文件。
- 网页可在后台实验中拖动历史滑块，返回当前时保留实验选择。回放读取已提交边界。
- 导出是流式 gzip 文件 `*-delta.json.gz`，包含动作、增量、快照、统计、经历、模型记录和未提交响应。导入先逐事件验证，在新实验名称下写入 MySQL，验证失败会清除该次导入的数据。

日结通常把回放跨度限制在一天内。关键词子串检索仍可能扫描该实验的摘要行；更大规模可按日分区，并根据中文检索需求增加 n-gram 全文索引。

## 本机配置与使用

需要 MySQL 8+，本次环境使用已有 MySQL 9.2 服务。仅创建项目数据库 `agent_world_sim` 和项目账号；凭据保存在被 Git 忽略的 `.env`。新环境先创建对应数据库和专用账号，再填写：

```dotenv
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_DATABASE=agent_world_sim
MYSQL_USER=agent_world_app
MYSQL_PASSWORD=本机专用账号密码
```

后端启动时创建项目表。脚本与网页通过同一个后端提交：

```bash
npm run dev
npm run simulate -- --mode scripted --population 20 --days 100 --out artifacts/new-run
npm run simulate -- --mode scripted --out artifacts/new-run --resume
npm run verify:run -- artifacts/new-run
```

继续实验时使用原运行模式。MySQL 实验必须位于项目的 `artifacts/<实验名>`，名称不可覆盖已有数据库实验。测试和旧格式工具可显式使用 `--storage files`。

实验目录只留下存储标记、进程锁、控制指令、少量运行日志和验证报告。世界、动作、快照、决策和待提交模型响应都存入数据库。浏览器本地演示模式仍使用 IndexedDB，后台实验使用 MySQL。

## 历史迁移与清理

```bash
# 单个实验：流式迁移，保留源文件
uv run --project backend python backend/migrate_storage.py experiment-name
# 迁移并在验证后清理；也可对已验证实验单独执行清理
uv run --project backend python backend/migrate_storage.py experiment-name --cleanup
# 从数据库独立重放所有增量并核对快照与最终状态
npm run verify:run -- artifacts/experiment-name
```

迁移先拒绝活动写入者，记录源文件 SHA-256；从初始快照逐条读取旧事件，独立应用旧补丁，并逐事件读回 MySQL 中实际保存的压缩增量进行比较。检查历史快照、最终检查点及原有字段顺序后，才使实验可见。清理前再次检查源文件和实验状态，只删除已纳入清单且已验证迁移的日志、重复导出、检查点、快照、响应和检索缓存。

迁移清单保存在 MySQL 的 `migrations` 表和实验目录的 `migration-report.json`。图片、未知文件和独立测试材料保留。可重复生成的两个端到端文件格式测试档案继续用于兼容测试。
