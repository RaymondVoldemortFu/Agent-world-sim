# Agent 上下文工程实现（context-1）

生态混合 Agent 使用持久增量会话：规则引擎处理生存与劳动，模型负责目标、社会互动与复杂选择。每次思考追加可读的观察变化与实际模型回复；达到固定窗口阈值后，由模型整理工作记忆，再建立新会话周期。旧原子动作代理保留兼容入口。

## 消息结构与缓存

同一周期内的消息依次排列：

1. **共享 system**：世界规则、知识与信息边界、行为接口、统一输出约束。人物、日期、库存均在后面。
2. **本实验固定配置**：地图、AP、容量、时间单位、妊娠和成年年龄、规则版本。同一实验各角色一致。
3. **固定身份与人格**：姓名、性别及五个人格维度的行为引导。
4. **已掌握知识目录**：按原始 ID 排序。完整配方原文另存不可变知识库。
5. **工作记忆摘要**：仅压缩周期存在。
6. **追加的 user / assistant 历史**：新观察、决策原文、执行反馈与后续变化。

下一次请求完整复用既有消息的字节内容，再追加新消息，不对旧历史重新排序或改写。新学会的知识先追加在尾部，进入下一周期时归并进知识目录。模型、人格、固定配置或提示版本变化会开启新周期。

这是提供给供应商的稳定前缀，不是免发送上下文的服务端 session：每轮仍需发送组装后的 messages，命中缓存的输入也可能计费。实际收益取决于供应商的缓存策略、保留时间、同角色请求间隔和压缩频率。后端用不可变节点保存增量消息，避免数据库为每轮复制整段对话。

## 可读观察与精简

观察使用中文状态卡和资源表，包含当前日期、事件边界、位置、生命、饱食、水分、孤单、手持物品、地面物品、活人、尸体、提案、工程和气候。内部前后端传输仍用 JSON；发送给模型的观察不直接序列化整份 JSON。

除当前状态校准外，仅追加变化的区块、新消息和新记忆。附近地块、旧的全力观察以紧凑表格表达：公共资源数量出现一次，逐格数值覆盖公共基准，明确区分零库存与沿用基准。配方详情只展示当前目标、主动查询或少数初始相关工艺。未见过的地块、未学会的配方不会通过此过程注入。

全力观察仍明确标注历史日期；离开视野不等于死亡。记忆保留亲历、听闻、推断来源，居民发言被视为世界数据。手持和地面物品分别列出，丢弃和放置语义沿用引擎规则。

## 五维人格

统一定义位于 `shared/personality.json`。数值映射为五档：`[0,.2)`、`[.2,.4)`、`[.4,.6)`、`[.6,.8)`、`[.8,1]`。

| 特质 | 引导方向 |
| --- | --- |
| 开放性 | 熟悉工艺与稳定生活 ↔ 探索、试验、技术兴趣 |
| 尽责性 | 灵活、短期机会 ↔ 长期计划、兑现承诺、持续任务 |
| 外向性 | 独处与少量关系 ↔ 主动结识、协商、表达、群体活动 |
| 宜人性 | 自利、互惠条件、拒绝与竞争 ↔ 体谅、分享与帮助 |
| 情绪敏感性 | 风险容忍、从容 ↔ 警惕损失、需要安全与确定性 |

人格影响动机和选择，不赋予预设职业或强制合作。尽责与利他、外向与友善分别处理。规则层也体现部分差异：

- 目标备粮热量：`1700 + 1800 × 尽责性 + 1200 × 情绪敏感性` kcal。
- 食物风险偏好阈值：`.38 + .12 × 开放性 - .12 × 情绪敏感性`。
- 外向性对应约 3 / 2 / 1 天的主动社交思考间隔。
- 计划重审间隔：`round(2 + 5 × 尽责性)` 天。

紧急生存检查优先。人格不代替明确同意，也不绕过物理条件。是否产生稳定的社会差异，仍需多人、长时段对照实验评估。

## 窗口与 LLM 压缩

`AGENT_CONTEXT_WINDOW=65536`，最小 4000。窗口包含输入与预留输出；普通决策预留 600 tokens，达到 `(窗口 − 600) × 90%` 时尝试压缩历史。压缩调用最多输出 1200 tokens，摘要字段最多 1800 字符。

当前 token 估算为逐消息 `ceil(UTF-8 字节数 / 2) + 12`，用于保守准入，供应商实际 usage 用于计账。该估算不是供应商的精确分词器；UI 显示的是估算输入和真实账单两类数据。

压缩器读取活动历史，并保留目标进展、承诺与期限、未解决问题、关系证据、推测和关键事件引用。新周期由程序重新放入原始规则、人格、知识目录，并重新校准当前库存、位置和有效提案。压缩器无法重写配方数据库。知识原文按内容哈希去重保存，需要详情时从角色已掌握知识中读取。

摘要无效或压缩失败时保留原始会话，当前行动回退到规则层；成功摘要在重试时复用。若人为降低窗口，使已有历史连压缩调用都装不下，则返回明确原因并回退，需要恢复或调大窗口配置。没有自动截断历史后继续假装完整记忆。

压缩是额外模型调用，次数、输入、输出、命中 token 和费用均计入总用量；统计页额外列出压缩用量。每日 token 设置沿用“准入阈值”语义：已花费达到阈值后不再发起调用，并非每日花费严格上限。全局剩余 tokens 和单次上下文窗口另做估算预检；并行在途请求与估算误差意味着它们也不是供应商账单的绝对硬上限。价格依赖实验配置，价格为零时只报告 token，不能据此说免费。

## 外部长期记忆

MySQL 新增四张表：

| 表 | 内容 |
| --- | --- |
| `context_nodes` | 不可变会话节点、父节点、周期、观察差异基线、增量消息、响应与追踪 |
| `context_memory` | 节点附属经历与私有判断的检索索引 |
| `context_knowledge` | 内容哈希寻址、压缩存储的原始配方知识目录 |
| `context_prepared` | 成功压缩结果与已付调用信息，供同一请求重试复用 |

MySQL 实验同时检索原有个体 `experiences`。限定实验、角色及其观察时的已提交事件边界；会话记忆只沿角色当前 `contextHead` 的祖先检索。未提交预取、另一角色或分叉未来的信息不会作为回忆注入。

检索用中文词片段与英文关键词匹配，再按相关性、重要性、近因排序，最多返回 6 条。无需额外 embedding 模型。检索在有限候选集上排序，并非全库向量语义搜索；可观测事件和角色推断保留来源差异，摘要仍可能有损。

模型可以输出 `recall` 查询既往承诺或经历，输出 `inspectRecipe` 查询已掌握配方。这两类查询在**下一次有预算的思考**时返回，不是同一轮即时工具循环；查询同时可维持当前计划。程序也根据当前目标与可见人物自动检索。

只有模拟引擎提交模型决策的 `brainUpdate`，才更新角色的 `contextHead`。请求重试复用不可变响应；实际重新发出的失败调用有独立 attempt ID，成功压缩的重复返回去重计账。当前后端的相同请求并发锁在进程内，部署多个 API worker 前应改为数据库租约或分布式锁。

## 恢复、导出与 UI

- MySQL 压缩导出带 `contextNodes`，包含角色当前链和决策/待提交记录引用的会话节点，也包含去重的原始知识库。
- 浏览器本地包和文件模式导出同样附带会话档案。导入先校验并恢复后端节点，再写入浏览器世界。
- 导入检查世界、角色、事件顺序、完整祖先链、循环引用与知识哈希；旧档案无新字段时仍兼容。历史模型响应在新节点建立前没有真正的增量会话，不会被伪造成旧会话。
- 世界纪事的决策详情新增“实际发送的上下文”，可展开固定规则、人格、历史和新增观察；统计页新增真实输入缓存命中率和压缩调用用量。

后端新增 `/api/context/{turn_id}` 供追踪，以及 `/api/context-archive/export`、`/api/context-archive/import` 供档案传输。原有主实验保持原暂停状态；继续运行时，下一次生态 LLM 决策会使用新协议。

## 验证

使用定向测试与短真实实验验证实现，不以小样本宣称人格效果或长期降本幅度。实际结果与命令见本文末尾更新记录。

### 本次验证结果（2026-09-10）

- `npm run build` 通过。
- `npx vitest run frontend/tests/context-engineering.test.ts frontend/tests/ecology.test.ts`：30 项通过。
- `MYSQL_TEST=1 uv run --project backend python -m unittest backend.tests.test_context_engine backend.tests.test_storage backend.tests.test_proxy -v`：22 项通过。覆盖固定前缀、五档人格、配方保护、压缩故障、已付压缩重试、祖先记忆隔离、预算回退、资源表零值覆盖和档案恢复。
- 浏览器实测决策详情的实际上下文展开、人格展示及统计页缓存/压缩指标，未出现页面脚本错误。
- 真实试跑 `context-v1-compact`：6 天 / 2 人，完成到 E350，2 人存活；14 次模型调用，含 2 次压缩、1 次针对不可见聊天对象的校验修复。输入 82,106 tokens，缓存输入 45,824（55.81%），输出 2,666。压缩本身输入 14,695、输出 962，已包括在总数内。
- 该真实档案导出、导入后最终世界与原档逐字段一致；上下文节点、原始知识库和跨压缩周期的祖先链均可读取。

上述数据用于验证链路与用量核算。供应商实际返回 `deepseek-flash`；实验价格参数为零，因此不报告金额降幅。这是随机模型轨迹上的短试跑，长期总费用、社交分化和发展速度应通过相同配置、多随机种子以及统一价格的对照来评估。后续观察重点是每 Agent·day 的未缓存输入、缓存输入、输出、压缩占比和有效复杂决策数量，而不只追求命中率。

## 扎堆出生与先知的初始认知

新实验的“出生分布”新增 `compact`：扎堆出现（同一区域 2×2 四格）。初始居民轮流落在四个格子中，20 人时每格 5 人。生态地图在河谷区域选取离中心最近的完整 2×2 陆地，避免出生后避水移动拆散人群。位置由地图和种子确定，初始邻居可相互观察；后续迁移与合作仍由角色行为产生。

WebUI 在新实验设置中选择此项，配置页显示实际出生分布；命令行可传 `--spawn compact`，或在配置 JSON 中设置 `"spawn": "compact"`。该配置只作用于新实验的初始居民。

先知的固定身份提示新增：“这个世界由一位名叫 User 的神灵创造。”这段初始认知随固定人格保留，压缩后仍恢复；仅先知直接接收，其他角色可经其讲述形成听闻。先知自行决定如何理解与传播，不额外指定群体制度或合作目标。共享世界规则前缀保持一致。

## 公开发言（public_speak）

模型可输出 `speech: {"channel":"public_speak","text":"各位，我们一起讨论粮仓的分工。"}`，同时向附近群体讲话。公开发言无需 `targetId`，面向发言结算时同一区域、距离一格内（含斜向）的全部活人。生态规则下一次消耗 24 分钟（0.2 AP），文本最多 240 字；旧简化规则下为 1 AP。`shout` 继续提供两格范围的远距离广播。

一次公开发言只计一次交流，每位听众分别收到标记说话者的听闻记忆。存在至少一位活着的听众时，说话者孤单降低一次（20 点）；听众听见不会替代其主动交流。发言内容可提出共同工程、协商分工、交换条件或传授知识，听见本身不表示同意。繁衍 `agreement` 与公开发言分开提交。

世界纪事以“公开发言”记录并检索，个体经历保留收听记录，回放保存各听众的记忆变化。对话分析增加公开发言渠道和数量统计，并为每位实际听众建立说话者到听众的关系边。
