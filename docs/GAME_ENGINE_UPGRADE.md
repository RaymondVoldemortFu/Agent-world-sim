# 榆树村：三维游戏引擎

2026-09-11。升级前的完整工作区已提交为 `1f2f9ea`。本版将连续村庄的主渲染器切换为 Three.js，并升级新实验的服务端空间规则与动作节奏。

## 使用

沿用统一页面与实验档案。在“开始新实验”中选择“三维村庄 · 游戏引擎”，可以使用脚本演示或已配置的LLM。游戏一天仍对应现实120秒。天数、请求预算、并发、上下文窗口和背包设置继续生效。

鼠标拖动旋转，右键拖动平移，滚轮缩放；WASD平移镜头。点击居民查看状态和决策，点击建筑查看村庄现场；小地图可以定位镜头。镜头工具提供全景、跟随居民、近看、昼夜光照、屋顶剖视、精细/流畅画质。选中室内居民会自动移除对应屋顶遮挡。回放使用相同场景与动作表现。

界面保留配置、统计、对话分析与实验档案。状态和经历成为场景右侧的浮动面板，画面内显示居民标签、发言气泡、目标及路径。

## 渲染与素材

建筑是真实的三维网格：石基、灰泥墙、木构与斜撑、三角山墙、逐片屋瓦、烟囱、门洞、门板、百叶窗、花箱，以及室内地板、桌子、粮桶和粮袋。住宅、工棚、大厅具有不同尺寸与屋顶。村庄包含石井、市集棚、车具、篱笆、长凳、耕作田条、树木、草地细节及边界外的河流和起伏地形。

人物由可以独立转动的头部、肩肘、髋膝等节点组成。行走朝向来自实际轨迹；耕作、进食、取放粮、发言和死亡有不同姿态。人物外衣、头巾或帽子、围裙、鞋和腰袋随个体而异。动画相位取自回放时钟，暂停会冻结行为。

Three.js处理透视相机、射线拾取、环境光、方向光、阴影、薄雾、透明烟粒和色调映射。白昼观察模式便于看清细节，也可切换跟随游戏时间的昼夜光照。所有素材由本地几何与Canvas生成，没有运行时素材下载。

静态网格和人物刚性部件按材质参数合并，颜色烘焙进顶点；关节保留独立变换。草使用实例化。阴影采用缓存更新；人物用轻量接触影。画质档控制像素比例和阴影。隐藏地图停止绘制，卸载时销毁几何、纹理和WebGL上下文。

## 服务端引擎

新实验标识为 `continuous-game-2`。世界仍由Node单写入队列推进，MySQL保存事件、轨迹和快照，客户端只呈现已提交状态。

空间定义位于 `frontend/src/continuous/game/space.ts`。同一建筑尺寸、入口宽度及城墙段用于生成三维模型和服务端碰撞。规划采用1.5米网格A*，对角色留0.55米间隙，再逐段检验并缩短路径。居民从住宅和大厅南侧门洞进入；井的交互点在井沿外。关闭庄园门会中断穿越该门的非持钥匙者路径，后续等待重规划。中途改目标从实际连续位置出发。

游戏时钟压缩率很高，原型的每秒1.2模拟米会让步行在现实几十毫秒内完成。新规则以可观看节奏标定动作：健康空载时约每现实秒15米，负重和低血量会降低速度；讲话至少3现实秒、进食至少2.5秒、取放粮至少2秒。它们统一换算成游戏时长并写入事件，而不是客户端随意延长动画。该节奏是游戏设计参数，不声称符合真实步行速度与全天时间比例。

事件推进仍解析每个动作完成边界，保留库存预留、任务中断、劳动累计、迟到计划校验和饥饿积分。新规则的自动进食按完成时实际饱食度结算至100。一天120秒、农业劳动总量与营养消耗保持独立参数。

LLM执行分为：

1. 在写入队列内准入、记录请求ID和计划版本、提交思考开始事件。
2. 固定这一时刻的观察快照和历史上界，在队列外分页读取经历并发起请求。
3. 回复进入写入队列，对请求ID、计划版本和角色状态重新校验后执行。

历史读取延迟和模型响应延迟均不会占用世界执行队列；每人至多一个在途请求，并遵守本轮并发上限和全局8请求限制。失败持久化会报告错误并停止该世界继续推进。

`game/presentation.ts` 在350ms缓冲内选择已提交状态与轨迹时间；既不把LLM计划直接当成结果，也不预测到数据库确认时间之外。页面切换、断线恢复和回放继续使用统一协议。

## 兼容与当前范围

旧的 `continuous-prototype-1` 档案可用三维场景打开，继续使用其原来的格点导航和动作时长。新实验应用游戏规则v2，避免篡改既有轨迹。离散领地/生态实验的规则与档案保留。

本次升级覆盖三维游戏呈现、空间导航、动作节奏和异步执行链。村庄仍为五名居民的当前场景；王税、使者、战斗和铭文尚未从离散领地迁入。角色间拥挤避让、完整室内家具碰撞、睡眠/体力、武器战斗动画及更大型领地地图可在此引擎上继续实现。目前居民可以在同一路段相互通过，装饰性草木和小件家具不属于导航阻挡。

## 文件与验证

- `frontend/src/continuous/Scene.tsx`：Three.js场景生命周期与交互。
- `game/models.ts`、`landscape.ts`、`characters.ts`：建筑、地景、人物和合批。
- `game/space.ts`、`navigation.ts`：共享空间和服务端路径规划。
- `game/rules.ts`、`world.ts`：新实验规则与工厂。
- `game/presentation.ts`：已提交状态的展示时钟。
- `scripts/continuous/server.ts`：墙钟、写入队列、异步模型调度与SSE。

测试覆盖实体门洞和墙体、路径中断、可见动作时长、进食、回放与步长不变性，以及慢历史IO/慢模型期间继续推进与迟到回复拒绝。浏览器验证镜头跟随、屋顶、暂停、导航干预、回放、配置持久化和对话分析。渲染截图位于 `artifacts/three-game-overview.png` 和 `artifacts/three-game-detail.png`。

性能观测使用Playwright的SwiftShader软件渲染器，不能代表用户设备GPU帧率；合批后的常规场景主渲染约64次绘制调用，开启阴影更新时增加一次阴影通道。流畅档进一步降低分辨率并关闭阴影，实际硬件帧率仍需在目标设备评估。

本轮验证结果：25个前端/规则/异步执行用例、4个MySQL与模型传输用例、4个浏览器用例通过，生产构建通过。另修复了时间轴拖动期间实时值覆盖所选回放时刻的竞态，并验证精确跳转至零时刻。已启动两天脚本演示 `continuous-1789120526556-b2c798`，模型调用预算为0；实际观察到补粮、连续行走和后续农活。

两天演示已完成：5人全部存活，模型调用0次，累计行走约956米、田间劳动约149.1人小时；服务端最终状态与同一时刻的MySQL回放完全一致。
