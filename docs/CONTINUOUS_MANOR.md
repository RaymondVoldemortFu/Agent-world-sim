# 鸦溪领地：连续模拟场景

新建连续实验默认选择「鸦溪领地」，保留榆树村五人演示选项。游戏一天为现实120秒；服务器结算世界，Three.js插值展示行走、劳动、说话与战斗。已有实验继续使用其保存的地图和设置。

## 初始化与经济

复用旧离散领地的初始化器，转换为24×24、每格15米的空间：领主、五名武装随从、村长、六个四人家庭，另加财政官西蒙#32。身份、家人、互助与田界纠纷保留在个人背景中；储藏和通行权限检查实际钥匙。庄园大厅内设keep-store，仅绘制一座大厅；家庭储藏、广场、水井、工坊、庄园围墙、王室道路和48块田保留。

每人每日消耗2500kcal，谷物3400kcal/kg，合0.735294kg。48块田每块每月需30人小时劳动、潜在产出37.5人日粮；满耕总产1323.529kg/月。收成按累计劳动比例结算，成熟粮仍需收割运输。默认D40起产量倍率0.5，第二次成熟时满耕产661.765kg。没有非农田食物来源。

新增财政官拥有独立口粮、庄园钥匙与账簿，庄园初始增加其35日储粮。庄园因此供养7人，日需5.147059kg，初始仓内180.147059kg。每个四人家庭初始35日储粮。负重包括粮食、材料、装备、钥匙和账簿，领地开局容量至少20kg，默认30kg。

## 王税粮仓与财政官

royal-tax-store设在庄园内(19,9)地块，独立于大厅口粮仓，初始为空。任何实际搬粮的人均可通过deliver/put/tribute存粮。首次D35日末、以后每30日，国王从此仓自动扣除应缴粮；欠款期间每日补扣。超额粮留仓，keep-store和家庭粮不会被自动扣除。

王税默认450人日粮，即330.882353kg/期。部分付款不重置连续欠款日期；全清才重置。首次欠税时使者进入地图；连续欠税严格大于2×拖欠限制（默认7日）或使者返回报告叛乱后派军。默认D35欠税，D49不出军、D50出军。派军后补缴不撤军。

财政官的每次观察附加当前引擎报表：

- 下次成熟日与剩余时间；按当前已完成及正在进行的劳动预计可收量；满耕潜力；已经成熟待搬的粮食。
- 下期应缴王税、到期日、已欠王税、欠税天数、王税粮仓存量与缺口。
- 庄园粮仓现存量、仍活着且住在庄园的供养人数、日耗粮与可维持天数。

这些是确定性数量，不把承诺或未完成劳动算作已经入仓的粮。只有财政官自动获得远方精确报表；其他Agent通过现场观察、对话和账簿获取信息。观察者可在统计页直接查看财政。

## 连续动作与日程

任务自动导航到实际交互点，并耗时结算；结算时重新检查接触距离、存量、负重和锁。可中断的动作在完成前不发生实物转移；田间劳动保留已完成部分。

基础任务navigate/supply/farm/deliver/rest/guard继续可用。新增take/put/give、tribute、craft、attack、break_lock/unlock/lock、write/show、report_rebellion。人物目标使用agent:ID，物品用item，质量用amount；supply表示补足随身粮到指定质量，take和give表示实际转移上限。工坊复用七种简化配方（矛、剑、盾、皮甲、镰、木板、刻刀）。尸体保留物品，可现场取走。

LLM居民初始只有自动吃随身粮至100饱食度。自主设置fetch、reserveDays和work，还可指定supplyStore、plots、depositStore、idleAt。显式任务结束后继续自动农活/存粮；自行开启的补粮日程会在携粮不足两日时优先补粮。脚本模式另有确定性的种田、存粮与取粮演示安排，不代表LLM社会决策。

战斗使用实际武器护甲、厅内防御与伤害，支持flee/low_hp/fight应对策略。王军是地图外确定性军队，追击所有当地活人、破锁进入建筑，具有外部补给。使者仍由LLM调查；亲见领主尸体只记录证据，必须自行判断并返回exit才能报告。使者死亡不会发送报告。

王军使用全图实时位置分配目标，锁定结果以 `missions[].targetId` 持久化并进入事件回放。优先保留有效的独立锁定，再按未分配目标、距离、人物ID的顺序分配；活目标不少于士兵时每人追击不同目标，目标较少时各目标的追击人数最多相差1。死亡、离场的居民和王室使者不参与目标分配。移动中的追击每30游戏分钟核对一次真实目标位置，目标移动超过6米或死亡/离场时重新寻路。

实际路径可通行时直接追击；被锁阻挡时，在保留实体墙体的前提下分析开门后的通路，攻击该通路上的第一道门，包括庄园门和房屋门锁。军队仍需真实走到门前、逐击扣除耐久，破门后继续追击原目标；路线分析使用的通行权限不写入士兵钥匙。多名士兵的路线经过同一道门时可以共同破门，但各自保留独立居民目标。

公共告示板可在现场读写。领主、村长、财政官各有个人账簿；持有人写入，show向指定活人提供当前文本副本，后续编辑不会自动传播。账簿可以整本转交。UI铭文页为观察者提供全量查看。

## 上下文、持久化与显示

共享规则、地图与配方在个人背景之前，沿用追加式历史和窗口压缩。财政数字进入个人观察尾部。每人最多一个在途模型请求，按最早应思考时间公平调度，模型IO不阻塞世界写入；迟到计划检查版本。王军不调用模型。

事件补丁支持追加新角色；Node回放、MySQL提交验证及历史回放均保留使者和军队。三维场景动态添加角色，也能在回放到其入境前隐藏。装备、告示板和独立税仓有实体显示，居民列表改为可横向滚动。暂停时切换页面或改变窗口尺寸会主动重绘。

## 验证

新增领地定向测试覆盖初始布局、精确财政、王税扣除与连续欠款、使者亲见/返程报告、实物钥匙、账簿隐私、连续耕作和回放。MySQL测试新增角色入境后的提交与回放。浏览器验证场景选择、32人、统计、账簿和页面切换。

`npx tsx scripts/validate-continuous-manor.ts`运行60天确定性基线，逐事件核对回放并逐日检查粮食守恒；覆盖正常收获、歉收、欠税、使者、王军和战斗。该基线不调用LLM，不衡量居民是否会自发形成有效税收合作。真实社会行为需要另开LLM实验观察。

连续模式的「Agent经历」页使用MySQL个人经历索引，包含本人计划、行动结果与实际听到的发言，支持关键词、来源、日期、稳定游标翻页和跳转回放。旧连续存档首次访问时分批补建索引。「当日新闻」复用共享新闻服务，开启后从首个已完成日开始补齐；素材取自精确的日末事件边界、全员身体状态、实物储藏及当日所有完成的对话，保留追加式上下文与独立模型用量统计。新闻任务在后台运行，浏览页面本身不会开启模型调用。
