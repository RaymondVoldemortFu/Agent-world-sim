# 连续模式运行卡顿修复（2026-09-11）

## 定位

对当前实验暂停快照做离线 CPU 采样，推进200个100ms墙钟对应的时间片，共产生513条事件。旧代码的主要热点为寻路碰撞检查、临时对象回收、事件比较和整个世界的深拷贝。单次推进最高约213ms，超过100ms调度间隔。

前端对每条增量事件深拷贝整个世界，再复制最新状态；同一批513条事件的画帧数据按完整JSON体积计约40MB。此外，标签循环在写入DOM后逐人读取clientWidth/clientHeight，每帧重复设置文字，每次seq变化都重新上传路线几何。

模型观察读取包含完整patch的事件页，在Node内最终只使用事件说明和听众等字段；样本2000条记录传输了约10MB。

## 改动

- 碰撞检查改为无临时数组的线段/矩形相交计算，并先做包围盒排除。A*缓存网格相邻边的碰撞结果；缓存键包含实际障碍物、门、锁、钥匙作用后的通行布局。每世界最多保留8组布局，不缓存Agent目标或完整路径。
- 事件记录缓存上次序列化的行和元数据，比较时每行只序列化一次，仅复制真正变化的内容。
- 前端历史帧使用不可变增量状态，共享静态地图和未改变的行；更新后历史帧保持不变。事件合并使用Map去重，回放帧定位使用二分查找。
- 地图尺寸通过ResizeObserver缓存，建筑布局每帧只计算一次，标签文字只在变化时写入。路线几何随实际路径/计划变化更新。
- 模型历史接口支持compact模式，移除patch后返回相同的事件字段和分页边界。回放仍读取完整事件。SSE广播给多个订阅者时只序列化一次。

## 本机验证

| 样本指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 200个时间片的引擎计算总耗时 | 2,920ms | 482ms |
| 单次推进P95 | 172ms | 23ms |
| 单次推进最大值 | 213ms | 53ms |
| 构建513个历史画帧 | 248ms | 9ms |
| 2000条模型观察事件传输 | 10,004,284字节 | 192,465字节 |

这些是同一快照的局部基准，不代表游戏时钟变快；游戏一天仍对应现实120秒。513条生成事件与原实现逐条完全一致。

独立32人脚本实验 `continuous-1789132426827-ab69f8` 在精细画质下，两次读取实际画面统计均为60 FPS；测试后已暂停并关闭临时页面。运行期间20次原实验状态请求中位数约3.9ms，最大约115ms，首次复杂寻路仍可能带来短时延迟。

29项前端/引擎/回放/缓存/异步运行测试、6项MySQL/网关测试及生产构建通过。新增验证覆盖门关闭、钥匙变化后的缓存失效、碰撞边界一致性、历史帧不可变性，以及compact观察分页。

原实验 `continuous-1789123107617-75b7fc` 保持暂停，游戏时间2735548057.4378276ms、模型规划次数1789均保持不变。
