# 原野 · Agent World

本地运行的 LLM 社会模拟实验。当前主场景「鸦溪领地」将中世纪村庄放进连续运行的三维世界：农户耕作、运输与交税，领主及家臣协调粮食与统治，地图外的国王按确定性规则追缴王税。歉收、信息差、私人储粮和武力共同构成社会压力。

LLM 负责交流、规划与自主设置日程；服务端引擎负责移动、劳动、饥饿、物资转移和战斗结算。Three.js 展示已提交的世界状态，MySQL 保存事件、轨迹、上下文与快照，可查询和回放。

## 快速启动

需要 **Node.js >=22、npm、Python >=3.11、uv 和 MySQL 8+**。在仓库根目录执行：

```sh
npm install
uv sync --project backend

# 首次配置：已有 .env 时保留原文件
cp -n .env.example .env
```

先在 MySQL 中创建项目数据库和专用账号，再编辑 `.env`：

```dotenv
DEEPSEEK_API_KEY=your-key-here
BASE_URL=https://api.deepseek.com
MODEL_NAME=deepseek-v4-flash
MAX_CONCURRENT_REQUESTS=8
AGENT_CONTEXT_WINDOW=100000

MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_DATABASE=agent_world_sim
MYSQL_USER=agent_world_app
MYSQL_PASSWORD=replace-with-local-password
```

后端启动时创建项目表。数据库连接设置见 [MySQL 存储文档的配置部分](docs/MYSQL_REPLAY_STORAGE.md#本机配置与使用)。模型配置由后端读取，密钥不发送到浏览器。

```sh
npm run dev
```

打开 [本地界面](http://127.0.0.1:5173/?engine=continuous)，点击「开始新实验」：

1. 执行模式选择「三维村庄 · 游戏引擎」。
2. 场景选择「鸦溪领地 · 32人 · 24×24」。
3. 选择「LLM 自主演化」或「脚本演示」，设置天数、并发、上下文窗口和经济参数。
4. 启动后在地图观察，使用「暂停 / 继续」控制实验，通过「实验档案」切换记录。

脚本模式的角色规划不调用 LLM，适合验证物理流程；LLM 模式需要有效的模型配置。新闻生成和 Agent 访谈也会各自产生模型调用。

后台服务存活时，关闭页面不会停止实验。新实验独立保存；配置页展示所选实验实际保存的设置，「配置下一次实验」用于新开局。

### 本地服务

| 端口 | 服务 | 职责 |
| --- | --- | --- |
| `5173` | Vite / React | 页面、三维场景与 API 代理 |
| `8001` | Node / TypeScript | 连续世界推进、动作结算、异步规划调度、SSE |
| `8002` | FastAPI | 连续实验 MySQL 存储、模型网关、经历、新闻和访谈 |
| `8000` | FastAPI | 统一 UI 的模型配置等共享 API |

`npm run dev` 启动以上全部服务，是完整 UI 的推荐入口。`npm run dev:continuous` 只启动 `8001` 和 `8002`；需要单独启动页面时执行 `npx vite --host 127.0.0.1`。统一 UI 的模型配置查询等共享功能仍会访问 `8000`，按需启动：

```sh
uv run --project backend uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

已有服务运行时应复用对应进程。

## 当前领地实验

### 人物与空间

开局共 32 人：领主、武装税收官、管家、3 名其他武装随从、村长、财政官，以及 6 个四人农民家庭。地图为 24×24 格，每格对应 15 米，包含庄园大厅、围墙与门、公共广场、住宅、工坊、48 块农田和实物粮仓。

身份与社会关系主要写在角色背景和提示词中，角色自行决定是否服从、合作或反抗。实际行动仍受钥匙、距离、库存、装备与身体状态约束。财政官是明确的特殊角色，可以从引擎获取准确的产量预测、收获日期、王税与庄园口粮数据。

### 农业与税粮

食物来自农田，每 30 天成熟一次，产量与实际完成的耕作劳动有关。每人每日消耗 2500 kcal，约合 0.735 kg 谷物。随身口粮、家庭储备、领主粮仓和王税粮仓分别记账，取粮和运输需要实际执行。

提示词中的征税流程为：

**农户 → 村庄粮仓 → 税收官运输 → 领主粮仓 → 领主安排税收官运输 → 王税粮仓。**

国王到期直接从王税粮仓扣粮；欠税期间每日继续扣缴。庄园口粮另算。发言、账簿和运输承诺不构成缴税，农户也不会因为提示词里存在税率就自动交粮。

使者在欠税后进入领地。连续欠税严格超过两倍欠税时间限制，或使者返程报告叛乱，会触发王军。领主死亡由使者观察和判断；王军采用确定性追击与破门规则。欠税时间限制是出军条件，不是免于缴税的宽限。

### 新实验默认值

| 设置 | 默认值 |
| --- | --- |
| 时间比例 | 1 游戏日 = 120 秒墙钟时间 |
| 实验长度 | 150 天，连续推进约 5 小时，暂停及故障等待另计 |
| 上下文窗口 | 100,000 tokens |
| 本轮规划并发上限 | 5；每个角色最多 1 个在途请求 |
| 普通背包容量 | 30 kg；持有马车时总负重上限 9999 kg |
| 农户惯例税率 | 50%，由角色组织实际征收 |
| 每期王税 | 450 人日粮，约 330.88 kg |
| 歉收 | `shockDay=40`，产量倍率降为 0.5 |
| 欠税时间限制 | 7 天；连续欠税严格超过 14 天触发出军条件 |
| 王军人数 | 10 |

配置定义见 [config.ts](frontend/src/continuous/config.ts)。内部模拟时间从 0 开始，UI 日数从 1 开始；分析具体收获或扣税时刻应使用事件时间与财政报表，避免日期边界差一天。

### 行动与认知

- **连续任务**：导航、耕作、取放粮、运输、转赠、制作、战斗和破门都有位置与耗时。移动可中断，已完成劳动保留；显式导航会关闭旧的自动移动任务，保留自动进食开关。
- **自主日程**：LLM 角色开局仅自动吃随身粮至 100 饱食度，补粮来源、储备天数、耕地与存粮等由角色自行配置。脚本模式有独立的演示安排。
- **局部感知**：普通说话和多人发言范围 12 米，大声说话 75 米，按结束时实际听众记录。破门声可被 150 米内角色感知，角色自行决定应对。
- **物理权限**：锁门可用钥匙开启或暴力破开；持钥匙者可在现场为另一角色授予指定门 1.5 天临时通行权。
- **持久交流**：公共铭文、个人账簿和私信有各自可见范围。普通信件一天后投递，寄往庄园成员的信由管家审阅；管家给庄园成员的快信在一游戏小时后抵达。
- **增量上下文**：共享规则前缀保持稳定，个人观察与经历追加到后部，达到窗口条件后压缩活动历史。连续规划不设累计调用/token 停机预算，也不主动设置截断性输出 token 上限；仍有并发、超时、格式校验及有限重试。

更多规则见 [连续领地](docs/CONTINUOUS_MANOR.md) 和 [税务、家臣、信件与门禁](docs/MANOR_HOUSEHOLD_UPGRADE.md)。

## 观察与调查

| 页面 / 功能 | 用途 |
| --- | --- |
| 地图 | 三维建筑、室内剖视、角色动作、发言与路径；点击角色查看右侧决策轨迹 |
| 配置 | 查看本轮设置，配置下一次实验 |
| 统计数据 | 存活、血量、饱食度、随身口粮、劳动、模型用量与领地财政 |
| Agent 经历 | 按角色、日期、来源及关键词查询，跳转事件回放 |
| 对话分析 | 基于轻量分类规则分析发言类型和意图，辅助观察交流模式 |
| 铭文 | 查看公共刻字与个人账簿；此页是观察者视角 |
| 当日新闻 | 用当日对话、人物状态、粮仓和前期新闻生成每日概况 |
| Agent 访谈 | 与任意存活、死亡或离场角色对话，检查其认知与理解偏差 |
| 回放与档案 | 切换实验，沿已提交事件和轨迹查看历史 |

镜头支持拖动旋转、右键平移、滚轮缩放及按当前视角方向移动的 WASD；可跟随居民、切换屋顶显示和画质。

访谈支持同一角色的多个独立会话、流式回答、Reasoning 开关、修改输入、重试与删除历史。每个会话冻结创建时该角色保留的上下文，访谈不会执行游戏动作或写回角色记忆。详见 [Agent 访谈](docs/AGENT_INTERVIEWS.md)。

新闻和访谈是辅助解释材料。判断某人是否真正交粮、听到消息或完成导航，应核对动作结果、实际听众与库存变化。

## 架构与持久化

```text
React / Three.js
  ├─ 连续 API / SSE → Node 世界服务 → 单写入队列与确定性引擎
  │                                  └─ FastAPI 网关 → MySQL / LLM
  ├─ 访谈 API / SSE ───────────────────→ FastAPI 网关
  └─ 共享配置 API ────────────────────→ FastAPI 共享服务
```

世界推进与模型网络等待分离：请求准入时固定观察边界，模型返回后重新校验计划版本再结算。客户端呈现数据库已确认的状态，动画不决定物理结果。

MySQL 保存压缩事件补丁、周期快照、模型决策、角色上下文、经历索引、新闻与独立访谈。回放应用历史补丁，不重新调用模型。提交具有顺序与幂等校验，存储故障时停止继续推进该世界，避免状态与数据库分叉。

主要代码入口：

- `frontend/src/continuous/`：状态、引擎、页面与配置；`game/` 为三维和空间实现，`manor/` 为领地规则。
- `scripts/continuous/`：世界服务、可靠提交、计划解析和观察构建。
- `backend/app/continuous_*.py`：持久化、模型上下文、回放、新闻和查询；`agent_chat.py` 负责独立访谈。
- `scripts/reports/`、`reports/`：数据提取、Python 图表及 HTML 报告。

备份、迁移或回滚前应确认实验身份和写入状态；回滚需同时处理事件、快照、未来上下文与派生记录。运行产物位于被 Git 忽略的 `artifacts/`，报告目录不替代数据库备份。

## 开发与验证

开发约定见 [AGENTS.md](AGENTS.md)。按改动范围选择验证：

```sh
# 类型检查与生产构建
npm run build

# 连续领地定向测试
npx vitest run frontend/tests/continuous-manor.test.ts frontend/tests/manor-household.test.ts
uv run --project backend python -m unittest backend.tests.test_continuous_state backend.tests.test_continuous_day_rewind -v

# 内存中运行 60 天确定性基线：回放一致性、粮食守恒与税务/战斗流程
# 不启动真实实验，不调用 LLM
npx tsx scripts/validate-continuous-manor.ts

# 全量检查（按需）
npm test
npm run test:backend
npx playwright install chromium
npm run test:e2e
```

数据库集成测试需要隔离数据。Playwright 可能复用已运行服务，后端测试启动过程也可能访问 MySQL；运行前检查测试初始化，避免影响正在运行的实验。

构建输出到 `dist/`；`npm run preview` 仅提供静态前端预览，不等同于启动完整 API 服务。
